## 3. Design

### 3.1 Data model

- No new collection. `cmsUpdates` and `cmsUpdates_drafts` gain two fields (#191): `category`, `null` or a trimmed string of 1 to 24 characters with no control character; `featured`, a boolean.
- Who writes: `cmsSaveUpdate` (draft), `cmsPublish` (live, history), the demo seed. Who reads: anyone, live and `visible == true`; staff and operators, both revisions.
- Contract in `packages/shared/src/update.cjs`: `UPDATE_CATEGORY_MAX = 24` and `validUpdateCategory(value)`. It is true only for a string whose trimmed length is 1 to 24 and that has no `/\p{Cc}/u` match (`no-control-regex` rejects `\u0000` ranges). `null`, `undefined`, and non-strings are false; the server handles `null` itself. Export both from `update.mjs`. The cap is 24, not 40: `Tag` never wraps, and 40 characters in the folio data face run past a 320px screen.

### 3.2 Endpoints

No new endpoint. No new `admin_logs` action. Tiers as a4 states them: `cmsSaveUpdate`, `cmsDeleteUpdate`, `cmsPublish` are **staff**; c1 does not touch the gate lines.

- **#190:** no server change. The editor calls `cmsSaveUpdate` `{ id, update, visible }`, `cmsPublish` `{ collection: 'cmsUpdates', docIds: [id] }`, and `cmsDeleteUpdate` `{ id }`. Existing log rows stand.
- **#191, `cmsSaveUpdate`:** add `category` and `featured` to `UPDATE_KEYS`. In `validateUpdateDoc`: a present `category` that is not `null` and fails `validUpdateCategory` adds `category: must be null or 1 to 24 characters on one line`; a present `featured` that is not a boolean adds `featured: must be a boolean`. Both keys are optional on the wire and always written: `contentFields` gains `category` (trimmed, or `null`) and `featured` (`update.featured === true`). Update the header comment (line 12). No other limit changes.

### 3.3 Rules changes

None. Category and featured are document fields under the existing visibility rule. Drafts stay admin only.

## 4. Security and privacy

- **Rules enforce:** anonymous and signed-in non-admin clients read only live `visible == true` updates; drafts are staff or operator only; nobody writes from a client. Unchanged.
- **On write:** the validator refuses unknown keys, a malformed category, a non-boolean `featured`, unsafe block links and image URLs (shared validators). The category is stored trimmed. Title and text are plain text, never HTML.
- **On read:** React renders the category, title, and text as text. The category renders only after `validUpdateCategory`; `featured` counts only when `=== true`. Rich blocks keep their existing read-side validation and `sanitizeHtml`.
- **Non-admin:** no `/admin` (`AdminGate`), 401 or 403 from all three endpoints, no draft read, no preview.
- **Staff admin:** lists, writes, previews, publishes, and deletes updates. Cannot turn `features.updates` on (`updateFeatures` is operator), so the notice says to ask an operator. Cannot read `admin_logs` (operator on a4).
- **PII:** none added. No text from strangers, so no new feature flag and no rate limit.

## 9. Decisions and open questions

**Decisions the builder may not change without the director:**

1. **No new endpoint and no rules change.** The plan says the endpoints exist; the editor wires `cmsSaveUpdate`, `cmsDeleteUpdate`, and `cmsPublish`.
2. **Page tier staff; "Updates" follows Content in the Content group; lazy routes; create at `updates/new/update`.** Content editing is staff, and a4 reads the tier from the docket entry only.
3. **The browser mints the new update's id once per form.** A retry after a failed publish cannot create a duplicate.
4. **A date-only control on the event's clock.** An unchanged day keeps the stored instant; a changed day stores noon in `config/event.timezone` (noon UTC without one); blank is undated. The admin and a3's public dateline show the same day. Nothing gates publish or the public list on the date.
5. **`featuredImage` and `content` are carried through unchanged.** No block editor in c1; the scope is the list, the editor, and the publish action.
6. **Category is optional free text, 1 to 24 characters, one line; `featured` is a boolean.** Both are optional on the wire and always stored (`null`, `false`). The rule lives in `shared/update`, which the server and the renderer already import, so write and read cannot disagree. 24 keeps the tag, which does not wrap, inside a phone screen.
7. **The lead is the first featured update in the public sort order, in its own "Featured" run.** Other featured updates keep their places. No server rule for a single featured update.
8. **Category is a plain `Tag` on the list only.** Not on the detail page, and not a filter.
9. **The admin list is a ruled table drawn in the page.** Each row needs the proof tint, which b1's `RuledTable` does not carry.
10. **Dispatch from a tip holding a4 and a3.** The tier field, the staff gate, the event-zone date helpers, `Standfirst`, and `Dateline` come from them.

**Open questions, each with the default the builder takes:**

- A state filter or a sort control on the admin list? Default: no.
- Show the category on the update detail page? Default: no.
- Show the lead and a tag in the specimen book's Updates figure? Default: no (a3's file).
- Rename the docket item to avoid "Updates" beside "Live updates"? Default: keep "Updates", the public page's word, with the description line.
- If a3 is not on the base: pass no zone (the base helpers ignore it), use the existing date line and body paragraph classes for the lead, and report it.
