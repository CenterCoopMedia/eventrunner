## 3. Design

### 3.1 Data model

- No new collection and no new field. Rules do not change.
- Reads: `session_materials` (server only, through the new list endpoint), `cmsSchedule` and `cmsSchedule_drafts` (admin listeners, existing), `speakers` (admin listener, existing). On a4 these three rules read `isAdmin()`, either tier; confirm it on the base.
- Writes: `admin_logs` rows from the archive endpoint only.

### 3.2 Endpoints

New module `functions/src/materials/bulk.cjs`. Export handler factories with injected deps (`db`, `auth`, `getConfig`, `bucket`, `log`), as `systemErrorsAdmin.cjs` does, plus pure helpers. Its `buildHandlers` wraps both handlers in `applyCors` as `systemErrorsAdmin.cjs` does, so the preflight is answered before the method check. Add one require and one spread to `functions/index.js`, and both names to `.github/smoke-endpoints.json`.

**`listAllSessionMaterials`** (POST, tier `staff`)
- Gate: `requireAdmin({ auth, getConfig }, req, { tier: 'staff' })`, before any read. Send the verdict's status on refusal (401 or 403).
- Request: `{}`. Other fields are ignored.
- Read: `session_materials` with `limit(MAX_LIST_ROWS + 1)`, `MAX_LIST_ROWS = 2000`. No index.
- Response 200: `{ materials: [{ id, sessionId, type, filename, reviewStatus, url, storagePath, submittedBySpeakerId, updatedAt }], truncated }`. `url` is null for a file; `storagePath` is null for a link. `updatedAt` is epoch milliseconds. `createdBy` and `createdAt` are not sent.
- 405 for any method but POST. 500 "Materials could not be listed." No `admin_logs` row, the same as `listSessionMaterials`.

**`downloadSessionMaterialsArchive`** (POST, tier `staff`, `onRequest({ region, timeoutSeconds: 540 })`)
- Gate: as above.
- Request: `{ materialIds: string[] }`.
- Validation, all before the first byte. Messages start with the field name, joined by `'; '`, so `fieldErrorsOf` (`adminApi.js`, line 52) splits them.
  - 400: not an array; empty; more than `MAX_ARCHIVE_FILES = 50`; a duplicate; an entry that fails `isValidDocId`.
  - 404: an id with no document ("materialIds: m9 does not exist"). Read the documents with one `db.getAll`.
  - 400: a link material ("… is a link; only files go in an archive").
  - 400: a `storagePath` that does not start with `session-materials/{material.sessionId}/`.
  - 404: a Storage object that does not exist, naming the filename.
  - 500: a `metadata.size` that is not a finite number after `Number()`. Parse each size once; never add the raw strings.
  - 413, code `too-large`: the sum of the parsed sizes exceeds `MAX_ARCHIVE_BYTES = 200 MiB`. The message states the total and the limit in MB.
- Audit, fail closed: one `db.batch()` with one row per material in the `logAdminAction` shape (`action: 'downloadSessionMaterialsArchive'`, `docPath: 'session_materials/{id}'`, `uid`, `email`, `at`), committed after validation and before the first byte. If the commit fails: log it, send 500 "The archive could not be recorded, so it was not built.", and stream nothing. Do not use `logAdminAction` here, because it swallows the failure.
- Response 200: `Content-Type: application/zip`, `Content-Disposition: attachment; filename="session-materials.zip"`, `Cache-Control: private, max-age=0, no-store`. No `Content-Length`: Cloud Run caps an HTTP/1 response that is not chunked at 32 MiB, so the body goes out chunked, as `downloadSessionMaterial` already does.
- Archive: `yazl` `ZipFile`. One `addReadStreamLazy` per file with `{ compress: false, size, mtime: updatedAt.toDate() }`, so only one Storage read stream is open at a time; then `end()`. Pipe `outputStream` to `res`. Bucket: `getStorage().bucket()`, the one `download.cjs` line 150 reads.
- Errors after the first byte go to one `fail(err)`. Attach it to each Storage read stream inside the lazy getter (yazl does not), to the `ZipFile` (size mismatch), and to `outputStream`. `fail` logs once, destroys the open read stream, and calls `res.destroy(err)`. It never calls `res.end()`, so the browser's body read rejects and no truncated zip is saved. If `res` emits `close` before the end (the admin left), destroy the open read stream.
- Entry names: `{sessionId}/{filename}`. Each part: replace `/`, `\`, and control characters with `-`; strip leading dots and spaces; cap at 150 characters and keep the extension; an empty result becomes `file`. A repeat name in one folder, compared without case, takes ` (2)`, ` (3)` before the extension.

## 4. Security and privacy

- **PII that leaves the deployment.** The archive carries speaker-authored files to the admin's device, the same data the per-file download already sends to an admin. The list response carries filenames, URLs, storage paths, and speaker ids; no email and no uid (`createdBy` is dropped). The coverage panel shows speaker display names from `speakers`, which an admin already reads. No new store, no new projection.
- **What the rules enforce.** Unchanged. `session_materials` is closed to every client (`firestore.rules` line 374). `session-materials/**` is closed in Storage (line 123). The endpoints are the only read path, and each one checks the tier on the server.
- **A non-admin.** Cannot reach the page (`AdminGate`, `AdminApp.jsx` line 54). Gets 401 or 403 from both endpoints. Cannot read `session_materials`, `speakers`, or drafts.
- **A staff admin.** Can list every material, download any file, and build an archive, embargoed files included (`canAccessMaterial` grants admins, `access.cjs` line 64). No archive is built unless its `admin_logs` rows commit. An operator can do the same.
- **Abuse cases.**
  - Bulk copying of embargoed decks by an admin account: allowed by design; recorded per material, fail closed.
  - A crafted request (thousands of ids, `../` or `..` ids): refused by the 50-id cap and `isValidDocId`.
  - A file material whose `storagePath` points outside `session-materials/{sessionId}/`: the archive refuses it. The existing `downloadSessionMaterial` does not check this; see Q1.
  - Zip slip through a filename such as `../../x`: entry names are cleaned; a test proves it.
  - A stored `javascript:` link written through the Admin SDK (the store checks only its own path): "Open link" is not drawn for it.
  - Resource drain: 50 files, 200 MiB, one read stream at a time, stored not deflated, 540 s timeout, and the read stops when the admin leaves.
  - A crashed instance or a silent truncated archive: every stream error reaches `fail`; the response is destroyed, never ended.
  - Server-side fetch of a link URL: never; links are refused.
  - Header injection: the download name is fixed ASCII.
  - Cross-site request: both endpoints need a bearer token in a header, not a cookie. `applyCors` allows only `EVENT_ALLOWED_ORIGINS`.
  - A lasting link: none is written. The browser holds a local object URL for one tick.

## 9. Decisions and open questions

Decisions the builder may not change without the director:

1. **No Cloud Storage signed URL. Stream through the function.** Signing needs `signBlob`, which a fresh project lacks (`download.cjs` lines 13 to 38, `media/upload.cjs` lines 8 to 17). Streaming checks access on every request. The only URL the browser holds is a local object URL revoked on the next tick, and nothing is written to a document, so the gap-table note holds. True signed URLs need an IAM grant in `init-event` and an operator step, outside #189.
2. **Build the archive on the server with `yazl` 3.3.1, pinned exactly.** The functions package has no zip writer (§2). A hand-written stored-only writer on Node 22's `zlib.crc32` would avoid the dependency, but it would own the local header, the data descriptor, the central directory, the UTF-8 flag, and the DOS time, and our own parser would be its only check. yazl has one dependency and streams lazily; 3.3.1 is the first release whose lazy getter runs once per entry. `archiver` 8 has nine direct dependencies. A browser zip would add a web dependency and N requests with no audit row.
3. **Store, not deflate.** Decks and PDFs are already compressed. Store costs no CPU.
4. **Limits: 50 files, 200 MiB, 540 s, chunked body.** They bound the run time and the browser's in-memory Blob. At the cap, 540 s needs about 3.1 Mbit/s; a slower link gets the stopped sentence and can select fewer files.
5. **Coverage rule.** Pending and approved count; rejected does not. Only live sessions with a non-removed speaker in `live.speakerIds` are considered. A speaker is named when none of their considered sessions has a counted material.
6. **Coverage is computed in the browser from the same array the table renders.** No coverage endpoint, so the panel and the list cannot disagree.
7. **Audit: one `admin_logs` row per archived material, fail closed.** No row for the list or the per-file download. The row shape does not change.
8. **Links are not archived and carry no checkbox.**
9. **Tiers: both endpoints, the page, and the existing materials gates are `staff`.** The parity plan puts materials with staff.
10. **List cap 2,000 with `truncated`.** Coverage is withheld when truncated, so it never states a partial count as whole.
11. **No shared admin table component from b5.**

Open questions, with the default the builder takes:

- **Q1.** `uploadSessionMaterial` accepts any `storagePath` (`store.cjs` line 406), and `downloadSessionMaterial` streams it to any speaker of the material's session. A speaker could register any object in the default bucket (another session's folder or another namespace) and read it. Default: b5 does not change it (out of scope). The archive checks the prefix. The director files an issue before #213 ships the speaker upload path.
- **Q2.** Does `{ tier: 'staff' }` admit an operator? Default: yes. Verify against a4's `requireAdmin` on the base.
- **Q3.** Archive folders use the session id, not the title. Default: the id; it is stable and needs little cleaning.
- **Q4.** Comments still say "signed URL" at `storage.rules` line 120, `store.cjs` line 154, and `projection.cjs` line 26. Default: leave them; a comment change in `storage.rules` would pull in the rules tier for no product change.
