## 3. Design

### Data model

No collection, field, index, endpoint, or queue. One browser key per account: `eventrunner.adminTour.v1:<uid>`, value `'done'`, in `localStorage`. The shell writes it when the tour ends. The shell reads it on mount. A throwing store reads as "not done", and ending the tour then holds for the life of the tab in memory.

### Endpoints and rules

None. The tour and the links read nothing new and write nothing to Firestore, so there is no `admin_logs` row. `firestore.rules` and `tests/firestore.rules.test.js` are unchanged.

### Section edit links (public)

- **`apps/web/src/components/SectionEditLink.jsx` (new).** Props `{ pageId, sectionId, label }`. It reads `useContext(AuthContext)`, not `useAuth()`, so a render with no provider is "not an admin". It renders `null` unless `adminStatus === 'admin'` (both tiers). Otherwise a react-router `<Link>` to `sectionEditPath(pageId, sectionId)` = `/admin/content/${encodeURIComponent(pageId)}/${encodeURIComponent(sectionId)}`. Visible text "Edit section", then `<span className="sr-only">: {label}</span>`, so the name is "Edit section: Details". Class: `textControlStateClass` from `controlClasses.js` plus `touch-target inline-flex items-center font-data text-caption font-medium text-text-primary underline underline-offset-4 no-print`. Same tab. It imports nothing under `src/admin`.
- **`SectionHead.jsx`.** New optional prop `action`, drawn last in the head row, after the running rule and the folio. It is never above the heading.
- **`SystemPage.jsx`.** `SlotSections` builds one `editLink` per section from the resolved `page.id`. The default draw passes it to `SectionHead` as `action`. A custom draw receives it as a third argument: `renderSection(section, blocks, editLink)`.
- **`Home.jsx`.** `info`: `SummaryRow`'s `facts` gains `action`, passed to its `SectionHead`. `sponsors`: `SponsorStrip` gains an `action` prop. `hero`: a `SectionEditLink` for `hero` as the last child of `EventHero`, after the action row, only when the page states a `hero` section. It is an `<a>`, never a `<p>`, so the E2E hero selector holds.
- **`ContentPage.jsx`.** A visible head takes the link as `action`. A section with an `sr-only` head takes it after its blocks and map, in a `mt-sm` line. A filtered-out section has no link. The trailing map is not a section and has no link.
- **Scope.** One link per drawn section. An empty section is not drawn, so it has none. The core of a system page (schedule grid, directories, updates list, logo wall) has none. No link per block or per field.
- **States.** `adminStatus` `'unknown'` or `'denied'`, signed out, and the static demo (auth is inert): nothing renders, and the reading order is unchanged. Keyboard path: the link follows its heading in DOM order; Enter opens the editor; "View site" in the rail returns. Focus: the public 3px ring.
- **Budget.** The public initial chunk may grow by at most 1,000 raw and 400 gzip bytes, on the normal and the demo builds (`node scripts/ci/bundle-budget.cjs --dist apps/web/dist` and `--dist docs/demo`). Record both builds before and after. No ceiling is raised. `ContentPage.jsx` is a lazy route, so only `SectionEditLink`, `SectionHead`, `SystemPage`, `Home` and `SponsorWall` count. If a build fails its ceiling on the tip (a3 left 1,968 gzip bytes, and c2 and c3 also spend it), stop and report to the director.

### The tour (admin)

- **Where.** An `<aside aria-label="Admin tour">` in `AdminLayout`, inside `admin-stone`, after c5's banner if present and before a4's `refused ? … : <Outlet />`. It is not a modal and not an overlay: the admin stays usable, and the reader can open each section while the tour stays on screen across routes.
- **Chunks.** `apps/web/src/admin/tourState.js` (new, static, small): `tourStorageKey(uid)`, `readTourDone(uid)`, `markTourDone(uid)`, each in `try/catch`. `apps/web/src/admin/components/AdminTour.jsx` (new) holds the copy, `tourSteps(docket)`, and the component. `AdminLayout` loads it with `lazy(() => import('./components/AdminTour.jsx').catch(() => ({ default: TourLoadFailed })))` inside `<Suspense fallback={null}>`, and only while the tour is open. `TourLoadFailed` (in `AdminLayout.jsx`, one line) is a `role="status"` paragraph "The tour did not load. Reload the page to try again." with an "End tour" button, so a failed chunk never leaves "Take the tour" as a control that does nothing. The admin entry chunk may grow by at most 1,000 raw and 350 gzip bytes. If it then fails the 50,000 gzip lazy ceiling on the tip, stop and report; do not move other pages.
- **Steps.** `tourSteps(docketForTier(adminTier))` returns: "Welcome to the admin"; one step per docket group the tier can reach; "Edit from the site". A group step's heading is `group.label`, or its first item's label where the label is null (b1's lead group). Its body is one copy line from `TOUR_GROUP_COPY[group.id]` (content, people, operations, system, and b1's `lead`), which names no page, because c1 to c5 add pages to these groups; then "In this group: " and the reachable item labels, joined "A, B and C". A group with no copy line shows only the list. A staff admin never reads an operator section.
- **Copy.** Welcome: "This tour shows where each part of the site is edited. End it at any step with End tour or the Escape key. Take it again from the foot of the rail." Then: "A change you save is a draft. Visitors see it only after you publish it. Each record shows one of three words:" and the three `RECORD_STATE_WORDS`. Groups: content "What the site says and shows."; people "Who takes part in the event."; operations "The event while it runs."; system "How this site is set up."; lead "How the event is going, in figures the server counts." Last step: "Open the site with View site. While you are signed in as an admin, each section of a page shows an Edit section link. It opens the editor for that section here." Run `npm run check:copy`.
- **Devices.** The desk's panel ground and rule (`rounded-admin-panel border-admin-hairline border-admin-rule-hairline bg-admin-ground-raised p-md`). An `h2` at `text-admin-lg font-bold`, `tabIndex={-1}`, with `aria-describedby` on the line "Step 2 of 6" in `text-admin-sm text-admin-ink-secondary` (language, so not the data face). The step line sits **under** the heading, never above it (eyebrow ban, `docs/interface-guidelines.md` line 63); then the body, then the button row. Buttons: "Back" and "Next" (on the last step "Finish tour") in `secondaryButtonClass`; "End tour" in `linkButtonClass`. The page keeps the one filled action. No motion, no scrim, no colour-only state.
- **Behaviour.** The shell reads the mark in an effect keyed on `user.uid`, so a sign-in as another account re-reads it. First visit (no stored mark): the tour opens at step 1 and does not take focus. "Take the tour" is a `<button>` first in the rail-foot button row, in `railButtonClass`; it opens step 1 and focuses its heading. Next and Back change the step and focus the new heading. On step 1, Back is native `disabled`. End tour, Finish tour, and Escape anywhere inside the aside end the tour: `markTourDone(uid)`, close, focus "Take the tour".
- **Tier and states.** The tour is shell chrome for both tiers. It has no route and no docket item. Loading: the chunk loads with no fallback, because the tour is optional. Error: a failed chunk renders `TourLoadFailed`; End tour closes it and "Take the tour" stays. Refused: a non-admin meets `AdminGate` and never mounts the shell.

### Seed and demo fixture

No change. The demo build has no auth, so it shows no link and no admin tour.

## 4. Security and privacy

- **Enforcement is unchanged.** The link is a convenience. `AdminGate` (`AdminApp.jsx`), a4's tier check in `AdminLayout`, `requireAdmin` in `functions/src/core/auth.cjs`, and `firestore.rules` decide every read and write, as today.
- **What a link reveals.** A page id and a section id, which the page already prints as `section-<id>` anchors, and the `/admin` path.
- **Stored text.** No text is written. Section labels are operator text from `cmsPages`; they render as React text nodes, never through `dangerouslySetInnerHTML`. Ids are URI-encoded. The storage value is compared to `'done'` exactly.
- **Non-admin.** Signed out, signed in, or pending: no link and no tour. A typed `/admin/content/…` URL meets the `AdminGate` denial.
- **Staff admin.** Sees every link. `content` is staff, so every link opens. The tour names only staff sections. **Operator:** the same, plus the operator sections in the tour.

## 9. Decisions and open questions

Decisions the builder may not change without the director:

1. **The tour is an inline aside at the head of the work surface.** Not a modal and not an overlay. A modal makes the admin inert behind it, so the reader cannot open what the tour names. The admin has no scrim, motion, or anchored-overlay device.
2. **Steps come from `docketForTier`.** One step per reachable group. New pages from b1 and c1 to c5 appear with no tour edit, and a4's one-place tier rule holds.
3. **Dismissal is per browser and account in `localStorage`.** No Firestore field, endpoint, or rule. "Dismissible" asks for nothing more. The key carries `v1`, so a rewritten tour can be offered again.
4. **The tour is its own lazy chunk.** Only the open state, `tourState.js`, one button and the one-line failure fallback join the admin entry chunk (at most 350 gzip bytes). a4 leaves about 1,073 gzip bytes under that ceiling, and c5 and others also spend it.
5. **Every link opens `/admin/content/<page>/<section>`.** That is the editor for the blocks a section draws. One small component, no import from `src/admin`, read through `useContext`.
6. **The link sits after the rule in the head row.** A section with no visible head carries it after its content. Nothing sits above a heading.
7. **Links are per drawn section only.** No link on a system page's core, an empty section, a block, or a field.
8. **No budget ceiling is raised.** The caps in section 3 hold, measured on both builds.

Open questions, with the recommended default:

1. Should the `venue_map` section link to Event settings, where the map is uploaded? Default: no. It opens its content section like every other; its section description already names Event settings.
2. Should the tour mark the rail group it describes? Default: no. The step names the group as the rail spells it.
3. Should the dismissal follow the account to other browsers? Default: no.
4. Should an admin see a link for an empty section? Default: no. An empty section is not drawn.
5. Should a system page's core get an "Edit" link to its collection editor (sessions, speakers, updates, organizations)? Default: no, out of scope for #198. Raise it as a follow-up if the owner wants it. The home `sponsors` link opens the section, whose one block is the lede; the wall itself is edited in c2's Organizations page. The ADMIN_GUIDE paragraph says so.
