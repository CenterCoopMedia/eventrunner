## 3. Design

### 3.1 Data model

- **No new collection. No rules change.** The slug is the document key of `cmsOrganizations/{slug}` and its draft. Firestore document identity makes it unique. The route, the OG card, the sitemap and the wall already key on the id, so none of them change.
- **Slug shape.** `SLUG_RE` above, at most 80 characters, checked on create only. An existing doc with another id stays editable. The slug never changes after the first save.
- **Fields** (who writes: staff or operator through the generic endpoint; who reads: anyone once published and visible, admins for drafts):

| Field | Stored | Rule at save | Editor control |
|---|---|---|---|
| `name` | string | merged result: required; trimmed; 1 to 120 characters | Name |
| `tier` | string or null | merged: trimmed; at most 60; blank is null | Tier, with a `<datalist>` of tiers in use |
| `order` | number or null | merged: a finite number | Order |
| `logoPath` | string or null | merged: `storageObjectPath` (`shared/venue`); at most 300; blank is null | Logo (`ImagePicker`, folder `cms-images`) |
| `url` | string or null | merged: `safeUrlHref` (`shared/urlSafety`), stored canonical; blank is null | Website |
| `description` | string or null | merged: at most 500 | Description |
| `bio`, `supportDescription`, `readMorePath` | string or null | only when the request sets the key: text; at most 5000, 2000, 200 | not in the editor; kept by the merge |

- The three profile fields are checked when a request sends them, not on the merged result, so a malformed value a script stored never blocks an editor save with an error on a field the editor does not show. The public page already guards each at render (`paragraphs`, the `readMorePath` pattern).
- Any other key passes through, as the generic endpoint does today. `visible` stays the reserved body flag.

### 3.2 Endpoints

No new endpoint. `cmsCreateContent`, `cmsUpdateContent`, `cmsDeleteContent` and `cmsPublish` serve organizations. **Tier: staff** for all four, stated by a4's gates; c2 adds no gate.

- **New module `functions/src/cms/organizations.cjs`:** `ORGANIZATION_SLUG_RE`, `ORGANIZATION_LIMITS` (the caps above, `slug: 80`), `organizationSlugError(docId)` (a message or null), `validateOrganizationFields(fields, sent)` returning `{ ok: true, fields }` normalized or `{ ok: false, errors }` (`sent` is the request's own `fields`, for the three profile keys). Messages name the field: `name: must be text`, `name: enter the organization's name`, `order: must be a number`, `url: must start with http:// or https://`, `logoPath: choose an image from the media library`, `slug: use lowercase letters, digits, and single hyphens, up to 80 characters`.
- **Seam in `content.cjs`:** `checkOrganizationFields({ collection, fields, sent })`, a no-op outside `cmsOrganizations`, called in both transactions after `checkBlockContract`. Its `fields` replace `references.fields` as the input to `checkSessionStructure`, so the trimmed, canonical values are what `writeDraft` stores. A refusal throws `RequestError(400)` with the errors joined by `; `, so nothing is written.
- **Create only (#193):** before the transaction, `organizationSlugError(target.docId)` answers 400. The 409 at lines 299 and 344 reads `slug: another organization already uses "<slug>"` for `cmsOrganizations` and is unchanged for every other collection.
- **Requests and responses:** create `{ collection: 'cmsOrganizations', docId, fields, visible }`; update the same; 200 `{ docPath, docId, status: 'dirty' }`. Publish `{ collection: 'cmsOrganizations', docIds }`.
- **Limits:** the caps above; `cmsPublish`'s existing 2000 ids. **`admin_logs`:** the existing rows. A refused save writes none.

## 4. Security and privacy

- **Rules (unchanged):** the public reads published, visible organizations only; drafts are admin (either tier); no client writes any `cms*` doc. Existing rules tests cover both collections.
- **Write side:** types, lengths, the URL scheme and the logo path shape are checked inside the write transaction. The URL is stored canonical. Strings are trimmed. The slug is refused unless slug-shaped.
- **Read side:** the `ContentContext` drop stays; its comment (and the two test comments at 330 and 368) change to say the save now checks types and the drop guards writes from scripts and the console. Names and descriptions render as React text. `isSafeHref` gates the link, `assetUrl` gates the logo path, `sanitizeHtml` gates `benefits`, and `SponsorDetail` keeps its `readMorePath` pattern.
- **Non-admin:** 401 or 403 from every endpoint before any read; can read published sponsor pages only. **Staff:** create, edit, publish and delete organizations and package blocks, and upload logos to `cms-images`; staff cannot write `branding/`. **Operator:** the same.
- **PII:** none. Organization records are public business facts; the editor says so. Invoice contacts are M11.
- **Abuse:** duplicate slugs are refused at save; every save and delete leaves an `admin_logs` row; deleting frees the slug.

## 9. Decisions and open questions

**Decisions the builder may not change without the director:**

1. **The slug is the document key, not a reservation collection.** The route, OG card, sitemap, wall and WebMCP label already key on the id. Firestore's create precondition already refuses a duplicate at save. There is no new store, no rules change, and nothing to release on delete.
2. **The slug is set once.** Changing it means delete and create. Links stay stable, and M11 invoices get a fixed key.
3. **Checks live in `functions/src/cms/organizations.cjs`,** run in the write transaction. Not in `packages/shared`, which avoids lockfile churn beside a3. The logo rule reuses `shared/venue` `storageObjectPath`, so the save and the render refuse the same paths.
4. **The six editor fields are checked on the merged result; the three profile fields only when sent;** other keys pass as today. The `ContentContext` drop stays.
5. **No new endpoint.** Every path is staff through a4's gates; the page is staff through its docket item.
6. **The editor covers the six issue fields.** `bio`, `supportDescription` and `readMorePath` are kept by the merge, not edited.
7. **Saving clears `seeded` and `seededAt`,** per `idempotency.cjs`, so a re-seed skips an edited demo sponsor.
8. **Admin vocabulary only:** a ruled table in the operator's order, "Publish all", no filter. The public detail page uses a3's `Standfirst` and `DefinitionPair`, which removes the eyebrow.
9. **`sponsor_package` is built from existing devices.** No new CSS, contract or specimen entry.
10. **The seed gives the sponsors page an empty "Sponsorship packages" section,** as the gap table asks and as `recap` and `guidelines` do; it draws nothing until an operator adds a package.
11. **Logos go to `cms-images`,** because `branding/` is operator only on a4.
12. **The create route is `/admin/organizations/_new`,** so no slug can shadow it. A form creates at most once.
13. **No budget ceiling is raised.**
