## 3. Design

**Summary.** Two PNG files, `branding/app-icon-192.png` and `branding/app-icon-512.png`, sit beside the manifest in every path. When `config/theme.logos.mark` holds an uploaded square PNG, both paths resample it. In every other case they write the committed neutral placeholder PNGs, byte for byte (drawn once in code from the default mark by a dev script). The manifest lists only these two files.

**Data model.** No new collection, field, or slot. Read only: `config/theme.logos.mark` (live in the publisher, snapshot projection in the deploy path). Read only: the `branding/…` object that path names, fetched anonymously over HTTPS.

**New module `scripts/lib/png.cjs`** (pure, `node:zlib` only).
- `encodePng({ width, height, rgba })`: 8-bit RGBA (colour type 6), filter 0, `deflateSync` level 9, CRC with `zlib.crc32`.
- `decodePng(buffer, { maxSide = 4096 })`: signature, then every chunk's length and CRC. Uses IHDR, PLTE, tRNS, IDAT, IEND. Concatenates every IDAT chunk before inflating (encoders split IDAT). Skips any other ancillary chunk (lowercase first letter: `sRGB`, `gAMA`, `iCCP`, `pHYs`, `tEXt`, `eXIf`, `acTL`, and the like); an APNG gives its default image. Refuses an unknown critical chunk and type 3 without PLTE as `unsupported`. Reads colour types 0, 2, 4, 6 at 8 bits and type 3 at 1, 2, 4, or 8 bits. Reverses filters 0 to 4. Refuses interlaced and 16-bit images. Refuses a side above `maxSide` before inflating. Inflates with `maxOutputLength` set to the exact size IHDR implies. Throws an error with a `reason` code: `not-png`, `damaged`, `unsupported`, `too-large`. Colour profiles and gamma are ignored (sRGB assumed).
- `resizeSquare({ side, rgba }, target)`: area average in premultiplied alpha, so a transparent edge does not darken.

**New module `scripts/lib/app-icons.cjs`.**
- `APP_ICON_SIZES = [192, 512]`; `appIconPath(size)` returns `branding/app-icon-${size}.png`.
- `PLACEHOLDER_MARK`: the default mark's numbers (ground `[91, 93, 97]`, ink `[250, 250, 249]`, ring radius 17 and width 4, dot radius 6, on a 64 grid). No hex.
- `renderPlaceholderIcon(size)`: the ground fills the whole square (full bleed, no corner radius), the ring and dot centred, 4 by 4 supersampling. The ring's outer edge is 19/64 of the side, inside the 40% maskable safe zone. Used only by the dev script and the tests.
- `PLACEHOLDER_DIR`: `apps/web/public/branding` (resolved from `__dirname`). `readPlaceholderIcons(dir = PLACEHOLDER_DIR)` returns the committed bytes. The runtime never re-encodes the placeholder: `compareDirs` diffs the demo byte for byte, and deflate output may change between zlib builds.
- `markObjectUrl({ mark, bucket })`: returns `{ url }` only for a trimmed `branding/{assetId}/{name}.png` path (extension matched case-insensitively; more than two segments, no leading `/`, no `..`, no scheme) and a non-empty bucket. Otherwise `{ reason }`: an empty slot or a `PLACEHOLDER_LOGOS` value gives "empty or still the placeholder"; any other flat or non-`branding/` path gives "not an uploaded file in the branding folder". The host is fixed; the bucket and path are `encodeURIComponent` encoded as in `og.cjs`.
- `iconsFromMark(bytes)`: decode, require width equal to height and 512 to 4096 pixels, resize to 192 and 512, encode. The output carries no ancillary chunk from the upload, so no `eXIf` or `tEXt` metadata ships.
- `resolveAppIcons({ theme, bucket, fetchImpl = globalThis.fetch, placeholderDir, maxBytes = 5 MiB, timeoutMs = 10000 })`: returns `{ source: 'mark' | 'placeholder', maskable, reason, files: [{ path, bytes }] }`. The fetch uses `AbortSignal.timeout` and `redirect: 'error'`, refuses a non-2xx status, and reads the body in chunks, stopping past `maxBytes`. A flat path, a path outside `branding/`, or an empty slot never fetches.
- `writeAppIcons({ distDir, theme, bucket, fetchImpl, log })`: writes both files under `distDir/branding/` and logs one line through `log.log`: `app icons: from the square icon slot (<path>)` or `app icons: neutral placeholder: <reason>`.
- Reason copy (plain, one fact each): "the square icon slot is empty or still the placeholder", "the square icon is not an uploaded file in the branding folder", "the square icon is an SVG, JPEG, or WebP file; app icons need a PNG", "no storage bucket was given", "the square icon could not be downloaded (<status or timeout>)", "the square icon is larger than 5 MB", "the square icon is not a PNG file", "the square icon is W by H pixels; it must be square", "the square icon is N pixels wide; it must be at least 512", "the square icon is wider than 4096 pixels", "the square icon uses a PNG format this build cannot read", "the square icon file is damaged".
- Fail soft. Any fetch or decode failure gives the placeholder. A filesystem write error still throws.

## 4. Security and privacy

- **PII.** None leaves the deployment. The only new network call is an anonymous GET of the project's own public `branding/` object, from the publisher and from the deploy build job. Re-encoding drops every ancillary chunk, so camera or GPS metadata in an uploaded PNG does not reach the icons.
- **What the rules enforce.** `config/*` writes are false for every client (`firestore.rules` line 25). `branding/` writes are false (`storage.rules` line 115). Only an operator, through `updateTheme`, can point the mark at a file. This spec changes neither.
- **Non-admin.** Cannot set the mark or upload a file. Sees only the published icons.
- **Staff admin.** Cannot change the icon: `updateTheme` stays operator. If a4 puts `mediaUpload` at staff, staff can store a PNG under `branding/`, but no slot points at it until an operator picks it. This spec adds no power.
- **Operator.** Picks the mark on the Branding page, as today.
- **Abuse cases.** A hostile or broken PNG from an operator: the side limit is checked before inflate, inflate has an exact `maxOutputLength` (decompression bomb), CRC and length checks reject damaged chunks, and any failure gives the placeholder. Size: 5 MiB byte cap while streaming and a 10 s timeout. SSRF: the host is fixed, redirects are refused, the path must start with `branding/` and contain no `..` or scheme, and the bucket comes from the deploy environment. Memory: a 4096 by 4096 image needs about 64 MiB of scanlines plus 64 MiB of RGBA plus the two outputs, well inside the job's 4 GiB (`--memory=4Gi`, `deploy-client.yml` line 482) and a hosted runner. These are Buffers, outside the 1536 MB V8 heap flag.

## 5. Tests

Not a bug, so not test-first. Every test builds its images in code; no image fixtures are committed.

- `scripts/lib/png.test.cjs` (new): encode then decode returns the same pixels. Each filter type 1 to 4 decodes (the test filters rows itself). Gray, gray plus alpha, RGB, palette with tRNS, and 4-bit palette decode to the right RGBA. A PNG with `sRGB`, `pHYs`, `iCCP`, `tEXt`, and `eXIf` chunks and its data split across three IDAT chunks decodes to the same pixels as the plain one (real exports carry both; a decoder that refuses them passes every other test here). Refusals: bad signature (`not-png`), bad CRC (`damaged`), an unknown critical chunk, interlaced, and 16-bit (`unsupported`), a side over `maxSide` (`too-large`, no inflate), and IDAT that inflates past the IHDR size (`damaged`). Re-encoding a decoded image with an `eXIf` chunk gives a file with no `eXIf`. Resize: a two-colour 1024 image gives exact halves at 512; transparent next to opaque white stays white, not grey.

## 9. Decisions and open questions

Decisions the builder may not change without the director:

1. **Source slot is `config/theme.logos.mark`.** It is square by intent ("Square icon") and is the manifest's icon today.
2. **No rasterizer dependency.** Uploaded PNG marks are resampled in pure code. SVG, JPEG, and WebP marks give the placeholder. Reason: the repo has no runtime rasterizer, and Playwright's browser is not in the publisher image, so using it is a new runtime dependency.
3. **One fetch path: the public download URL, in both scripts.** Reason: the deploy build job has no credentials, `branding/` is public read, and no IAM change is needed.
4. **Fail soft.** An icon problem logs its reason and ships the placeholder; it never fails a publish or a deploy. Reason: the icon is cosmetic and must not block content.
5. **Placeholder drawn in code from the default mark's numbers, full bleed, committed as two PNGs, with a drift test against `mark.svg`. The scripts copy the committed bytes; they never re-encode them.** Reason: the `og-default.png` precedent, the default mark must give valid icons with no rasterizer, and `build-demo --check` compares bytes.
6. **Maskable only for the placeholder.** An uploaded mark gets `any`. Reason: its safe zone is unknown.
7. **The manifest drops both SVG entries.** Reason: Chrome may pick the placeholder SVG over a client's PNG, and SVG adds nothing to the check.
8. **Fixed names `branding/app-icon-192.png` and `app-icon-512.png` in every path.** Reason: the fallback stays field-for-field equal to the builder's neutral output.
9. **Size rule: square, 512 to 4096 pixels.** Reason: no upscaling, and bounded memory.
10. **The two PNGs go in the feature commit, not the regenerate commit.** Reason: they are source assets, like `og-default.png`. Unlike that file, a unit test in CI guards their freshness.

Open questions, with the recommended default:

1. Test an uploaded mark's safe zone (opaque, uniform outside 40%) to allow `any maskable`? Default: no.
2. If `Page.getInstallabilityErrors` is not available in the sandbox's `chromium-1194`, what counts as evidence? Default: keep the spec (CI installs the full build), and say plainly in the report that the "Done when" line is not verified locally.
3. If Chrome reports a service worker error? Default: stop and report; a service worker is out of scope for #218.
4. Keep the one-line hint on the Branding page? Default: yes; it is where the operator learns the PNG rule.
5. Cache-busting for a changed icon under the same name? Default: none; Hosting's default cache applies.
6. An `apple-touch-icon` link in `index.html`? Default: out of scope.
