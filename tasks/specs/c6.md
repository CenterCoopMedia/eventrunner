## 3. Design

### 3.1 Data model, endpoints, rules

- No new collection, field, or type. A richtext field stays an HTML string. Who writes: staff and operator through `cmsCreateContent` and `cmsUpdateContent`, then `cmsPublish`; the seed. Who reads: anyone for live and visible docs; either admin tier for both revisions.
- No new or changed endpoint. The existing `admin_logs` rows are written unchanged. No rules change and no rules test.

### 3.2 Client

Files: `apps/web/src/lib/sanitizeHtml.js` (one export), `apps/web/src/admin/richText.js` (new, pure), `apps/web/src/admin/components/RichTextField.jsx` (new), `AdminContentBlockEditor.jsx` (the richtext branch).

- **The allow list, shared.** `sanitizeHtml.js` exports `RICH_TEXT_TAGS = Object.freeze([...ALLOWED_TAGS])`. Never export the live `Set`: a caller could widen the policy.
- **The toolbar table** (`richText.js` `TOOLBAR_CONTROLS`, frozen, in this order). Each row names its label, the tag it produces, and its command:

  | Label | Tag | Command | Shortcut |
  |---|---|---|---|
  | Bold | `strong` | `bold` | Ctrl or Cmd+B |
  | Italic | `em` | `italic` | Ctrl or Cmd+I |
  | Link | `a` | opens the link row | Ctrl or Cmd+K |
  | Heading | `h3` | `formatBlock h3`; `p` when pressed | |
  | Subheading | `h4` | `formatBlock h4`; `p` when pressed | |
  | Bulleted list | `ul`, `li` | `insertUnorderedList` (toggles) | |
  | Numbered list | `ol`, `li` | `insertOrderedList` (toggles) | |
  | Quote | `blockquote` | `formatBlock blockquote`; `p` when pressed | |

  No `h2` control: the section title is `h2`. No control for `hr u s code pre`. Stored content with those tags is kept, because they are allowed.
- **The field.** `RichTextField({ label, value, onChange, error, hint })`, lazy in `AdminContentBlockEditor.jsx`: `const RichTextField = lazy(() => import('../components/RichTextField.jsx'))` inside `<Suspense>`. The richtext branch keeps `sm:col-span-2`. Because the branch keys on field type, `richtext.value`, `faq_item.answer` and c2's `benefits` all get it. Hint: "Select words, then choose a format. Pasted text keeps its words and loses its formatting."
- **Markup.** The label is a `<span id>` in `fieldLabelClass`; a click on it focuses the editor. A `<label>` cannot point at a `div`. Under it: the hint, then `role="toolbar"`, `aria-label="Formatting"`, `aria-controls` the editor. Then the link row when open, a `role="status"` line, and the editor. The editor is a `div` with `contentEditable`, `role="textbox"`, `aria-multiline="true"`, `aria-labelledby`, `aria-describedby` (hint, error), and `aria-invalid`. Last comes `FieldError`. Buttons are `type="button"` with `aria-pressed`; Bold, Italic and Link carry `aria-keyshortcuts` ("Control+B Meta+B").
- **Load.** The editor's DOM is never written from React children. A `lastEmitted` ref holds the last value sent up. When `value` differs, the field sets `innerHTML = sanitizeHtml(value) || '<p><br></p>'`. On focus it runs `execCommand('defaultParagraphSeparator', false, 'p')`.
- **Save shape.** `richText.js` `serializeRichText(html)` parses in `new DOMParser()` (inert). It renames `b` to `strong` and `i` to `em`. It turns a `div` with no block child into `p` and unwraps any other `div`. It wraps top-level inline runs in `p`, drops a trailing `br` in a block, drops blocks with no text (not `hr`), and turns U+00A0 into a space. It returns `sanitizeHtml(result)`, or `''` when no text remains, so `validateRequiredContent` still fires. Contract: `sanitizeHtml(out) === out`. The `input` event and every command end in `onChange(serializeRichText(editor.innerHTML))`.
- **Paste and drop.** `paste` is cancelled. The field reads `text/plain` only and inserts `plainTextToHtml(text)`: escaped, one `<p>` per non-empty line, through `execCommand('insertHTML')`. `drop` is cancelled.
- **Keyboard path.**
  - Tab order: toolbar (one stop), the link row when open, the editor. Tab leaves the editor; nothing traps focus.
  - In the toolbar: Left and Right move and wrap; Home and End jump; Enter and Space activate. Escape returns to the editor. The roving index stays on the last control used.
  - In the editor: Alt+F10 goes to the toolbar. Ctrl or Cmd+B, I and K run Bold, Italic and Link. Ctrl or Cmd+U is cancelled, so the editor never makes a `u`.
  - The field saves the editor range on `selectionchange` while the selection is inside it. Before a command it restores that range. After the command, focus returns to the editor. `onMouseDown` on a button calls `preventDefault`, so a click keeps the selection.
- **Pressed state.** `formatsAt(node, root)` lists the tags from the selection's anchor up to the editor (`b` counts as `strong`, `i` as `em`). The field recomputes it on `selectionchange`, `input` and each command.
- **Link row.** With nothing selected, Link writes "Select the words to link first." in the status line. Otherwise a `TextField` "Link address" opens with focus, prefilled when the selection is in a link. Then "Add link" (`createLink`), "Remove link" (`unlink`, only in a link), and "Cancel". Enter adds; Escape cancels; both return focus to the editor. `isLinkAddress(v)` accepts `isSafeHref(v)` values that start with `https://`, `http://`, `mailto:`, `tel:`, `/` or `#`. A refused address gets the field error "Use an address that starts with https://, mailto: or tel:, or a path on this site that starts with /."
- **Devices and look.** Admin tokens only (`adminIdiom.test.js` scans the new files). The editor takes `inputClass` and is about six lines tall. Allowed tags get admin-token styles through arbitrary variants in the class string. Headings use `text-admin-lg` and `text-admin-base` bold. Lists get markers. A quote gets a leading rule in `admin-rule-strong`. Links get `admin-ink-link` with an underline. Code uses `font-admin-data`. Toolbar buttons take `secondaryButtonClass` plus `aria-pressed:` weight, `admin-action-soft` ground and the action rule, so a pressed control shows weight, ground and `aria-pressed`, not colour alone. Words, no icons, no motion, no `index.css` edit.
- **States.** Loading: the Suspense fallback is a hint-styled line, "Loading the rich text field…". A failed chunk reaches `ChunkErrorBoundary`, as `DeferredAdminPage` does. Error: `aria-invalid`, the alarm rule, and the message; `ServerErrorSummary` as today. Empty: no placeholder; the hint says what to do. Refused: nothing new, since the Content item is staff on a4 and `AdminGate` (54) turns away non-admins. Busy and success stay on the page's buttons and `SaveStatus`.
- **Route, docket, tier.** No new route or docket item. The block editor routes (131–141) stay under Content, the third item in the Content group, `tier: 'staff'` on a4. No `AdminApp.jsx` edit.

### 3.3 Public renderers, seed, demo

- No renderer change. `.rich-text` already styles every tag the toolbar makes. No `index.css` edit (a3 edits it heavily).
- No seed or fixture change. The E2E restores the block it edits.

## 4. Security and privacy

- **Rules:** unchanged (32–40). Clients never write `cmsContent` or its drafts. Drafts are admin only; on a4 `isAdmin()` is operator or staff.
- **On write:** the server stores the string as sent, as today. The editor sends only serializer output, a fixed point of `sanitizeHtml`. A direct API call can still store any string; every read path sanitizes it.
- **On read:** the public renderers sanitize as today. c4's history shows tags as text.
- **The new sink is the editor itself.** Load assigns only `sanitizeHtml` output to `innerHTML`. Paste inserts escaped text only, and drop is refused. The serializer parses in a `DOMParser` document, never in a detached node of the live page: an `img` there still loads and fires `onerror`. Without this, a staff admin could store `<img src=x onerror=…>` through `cmsUpdateContent` and run script in an operator's session when the operator opens the block.
- **Links:** `javascript:` and `data:` are refused at the link row and dropped by the sanitizer. Every kept link carries `rel="noopener noreferrer"`.
- **Who can do what:** a non-admin reaches no admin route, reads no draft, and writes nothing. Staff and operators can edit every richtext field and publish it. Nothing operator-only changes. No personal data is involved.

## 9. Decisions and open questions

Decisions the builder may not change without the director:

1. **No new dependency.** Use the browser's editing commands (`document.execCommand`) and a serializer through `sanitizeHtml`. Reason: eight commands, one allow list, and a4 leaves 1,073 gzip bytes in `AdminApp`. A TipTap or ProseMirror editor adds a second schema and serializer to keep in step with `ALLOWED_TAGS`.
2. **The field is its own lazy chunk**, loaded inside the block editor. Reason: the budget, and no edit to `AdminApp.jsx`, the most contended file.
3. **Sanitize on load, plain-text paste, refused drop, inert parsing.** Reason: the editor is a new HTML sink, and without these a staff account can reach an operator's session.
4. **The eight controls in §3.2; headings are `h3` and `h4`.** Reason: the section title is `h2`; the list stays small and inside the allow list.
5. **No server change.** Reason: `functions` has no HTML parser; every read path already sanitizes.
6. **The stored value is the serializer output, a fixed point of `sanitizeHtml`**, with `strong` and `em`, `p` blocks, plain spaces, and `rel` on links. Reason: then render strips nothing, and a test can say so exactly.
7. **ARIA toolbar with one tab stop, Alt+F10 and Escape, focus back to the editor after a command.** Reason: the guidelines' roving index pattern, plus a way back to the text.
8. **Link addresses start with https, http, mailto, tel, `/` or `#`.** Reason: `isSafeHref` treats `example.org` as a relative path.
9. **A new E2E file.** Reason: the covered HTTP flow in `cms-publish.spec.js` does not change, and c2 and c4 already edit that file.

Open questions, with a recommended default:

- Should the server refuse tags outside the allow list? Default: no, not in #197. Raise it when a non-web consumer (mail, PDF) reads rich text.
- Firefox wraps a block in `formatBlock blockquote`, and CI runs Chromium only. Default: the serializer keeps output inside the list. The builder checks Firefox by hand if one is available and says so in the report.
- Add evidence captures of the Value panel with the toolbar (light and dark, 1440px, full scale) under `docs/plans/evidence/c6/`? Default: yes, in commit 1, following `pr-262`.
- A specimen book entry? Default: no. The book draws public devices on public tokens, and wave 6 owns the admin devices' evidence.
- A "Remove formatting" control or a source view? Default: no.
