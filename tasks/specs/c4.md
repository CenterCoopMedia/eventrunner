## 3. Design

### Data model

No new collection, field, index or queue. `publishDocs` stays the only writer of revision rows. The endpoint is the only reader the page uses. The record list reads the live and `_drafts` collections that the rules already open to both tiers.

### Endpoint

`cmsGetVersionHistory` stays one endpoint in `functions/src/cms/versions.cjs`. POST, tier staff (a4's line stays). Request, validation and limits do not change. No `admin_logs` row: it is a read. No rate limit: it is an admin read.

The response keeps `{ entries, nextCursor }`. Each entry is shaped by a new `toEntry` with named fields only:
- `id, docPath, revision, fields, visible, publishedBy, publishedByUid` as stored (`publishedBy` null when absent). The page never reads `fields`; it is kept so the existing cases pass.
- `publishedAt`: milliseconds through a local `toMillis` (a copy of `systemErrorsAdmin.cjs` 73–82: `Date`, `toMillis()`, number, ISO string), or null.
- `previousRevision`: the next row's revision, or null for the oldest stored row.
- `changes`: `describeChanges(previous, current)`, capped at `MAX_CHANGES = 50`, and `moreChanges`: the count past the cap.

The predecessor of each entry is the next row in the result. The query already reads `pageSize + 1` rows, so the last entry on a full page has its predecessor too. There is no extra read. When the result holds `pageSize` rows or fewer, the last entry is the oldest stored row.

`describeChanges(previous, current)` is pure and exported in `internals`:
- Flatten `fields` to leaf paths joined by `.`. A plain object (prototype `Object.prototype` or null) recurses by key. An array whose items are all scalars is one leaf. Any other array recurses by index. An empty object or array is a leaf.
- An instant is a leaf: a `Date`, or anything with a `toMillis()` (a `Timestamp`). Compare and send it as milliseconds through the same `toMillis`, and mark the change `time: true` when either side is an instant. Any other non-plain object is a leaf compared with `util.isDeepStrictEqual`.
- Skip the top-level paths `seeded` and `seededAt`. They are seed bookkeeping, not an edit.
- With no predecessor, every leaf is `{ path, kind: 'added', before: null, after }`.
- Otherwise compare the union of paths in sorted order: `added`, `removed`, or `changed` (deep equality on the leaf value). Unchanged leaves are left out.
- Add the path `visible` when `visible` differs from the predecessor, or on a first row that is hidden. `visible` is a reserved field (`store.cjs` 37–57), so no content path can collide with it.

## 4. Security and privacy

- Rules: no client writes `cmsVersionHistory` or any live or draft collection (`firestore.rules` 32–97). Only admins of either tier read them (a4). Nothing changes.
- On write: nothing new is written. History rows come only from `publishDocs`, from drafts that passed the existing save validators.
- On read: every stored value is shown as text. A `<script>` or `<img onerror>` in a field is a string of characters on this page. Rich text shows its tags; it is not parsed. A stored URL is not a link, so a `javascript:` value cannot run.
- Signed out: the endpoint answers 401, and the route goes to `/signin` (`AdminApp.jsx` gate).
- Signed in, not an admin: the endpoint answers 403, the gate shows its denial, and a direct Firestore read fails.
- Staff: reads every collection's history and every record list. Cannot change or delete a version: no write path exists. An operator has the same access here.
- Privacy: a version names the publisher's address. Staff can already read `updatedBy` addresses on every draft, so nothing widens. Nothing leaves the deployment. The search text is a record name, not personal data, so it may sit in the URL.
- Residual: a value published by mistake stays in history. Removing it is a console task (open question 7).

## 9. Decisions and open questions

Decisions the builder may not change without the director:
1. **The diff is computed on the server, from the row the query already reads.** No new endpoint, field, collection or index. Reason: every entry, the last on a page included, has its predecessor at no extra read, and the page stays a renderer.
2. **The response change is additive, except that `publishedAt` becomes milliseconds.** Reason: a `Timestamp` has no `toJSON`, and nothing reads the field today.
3. **Nested values are flattened to paths.** Arrays of scalars stay whole. An instant is one leaf in milliseconds. `seeded` and `seededAt` are skipped, `visible` is shown, and an entry holds at most 50 changes. Reason: pages and sessions read as well as content blocks, and seed bookkeeping is not an edit.
4. **One collection at a time.** The filter is a required select, default Content blocks, kept in the URL. Reason: the endpoint is per record, and one choice costs two listeners where "All" costs twelve.
5. **The record list reads the current live and draft documents.** A record with neither is not listed; its route still works. Reason: Firestore has no distinct query, and the plan says a cross-collection feed needs a second endpoint.
6. **The account shown is the publisher (`publishedBy`).** Reason: that is what the row stores. Recording the draft's editor changes `publishDocs`, outside #195.
7. **Every stored value is text.** Rich text shows its tags, and a URL is not a link. Reason: no parser and no sanitizer are needed, and the page shows exactly what was stored.
8. **Staff tier for the endpoint and the page. No `admin_logs` row for a read.** Reason: content editing is staff (a4), and a read writes no audit row (`listSystemErrors` precedent).
9. **No rules change; one rules test.** Reason: a4's rules already admit both tiers to every collection the page reads, and the new case pins the list query the page runs, which a4's `getDoc` matrix does not.
10. **Docket: Content group, last, "Version history", route `versions`.** Reason: "History" alone collides with the public history section (#194).
11. **Deviations from the design record, for the director to accept.** The version list has no sort control: it is in version order. The record list has one ("Order records by"). There is no bulk-action row: no action applies. The collection filter is one required select, so it has no active count and no clear control.

Open questions, each with a recommended default:
1. Restore a past version? Default: no. It needs a write endpoint and an audit row, and the Done when line does not ask for it.
2. List deleted records, or a feed across collections? Default: no. It needs a second endpoint (plan line 101).
3. Record the draft's last editor on the history row? Default: not in #195. A follow-up edits `publishDocs`.
4. Show `init-event-script` as words ("Setup script")? Default: show the stored value in mono, since the machine owns it.
5. Add a "Version history" link to each editor? Default: not in #195. #198's section edit links touch the same editors.
6. Which clock? Default: the event clock with its zone label, as b2 chose.
7. Remove a version published by mistake? Default: out of scope. Nothing deletes history rows today. File a follow-up.
8. Show `config/*` rows (`admin/config.cjs` 355–361; a4 452–460)? Default: no. They are operator settings with no version number.
