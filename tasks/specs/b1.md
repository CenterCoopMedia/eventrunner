## 3. Design

### 3.1 Data model

- **No new collection. No new rule.**
- **`config/event.milestones`** (#180): `null` or an array of at most 20 `{ label, date }`. `label` is a trimmed non-empty string of at most 80 characters. `date` is `YYYY-MM-DD` and passes `isValidCalendarDate`. Any other key is refused by name. Readers sort.
- **`config/event.registration.goal`** (#180): `null` or an integer from 1 to 1,000,000.
- **Who writes:** only `updateEventConfig` (staff tier on a4). `EVENT_EDITABLE_KEYS` gains `milestones`. The goal sits inside `registration`, already editable.
- **Who reads:** anyone. `config/event` is public and ships in the generated bundle. The plan chose this store; the editor says so.
- **Server reads** (#178): `count()` over `users`, `tickets`, `speakers`, the six publishable collections and their `_drafts`, and `system_errors`. No document body leaves the function.
- **Client reads** (#182): `sessionBookmarks` (public) and the admin's existing `cmsSchedule` and `cmsSchedule_drafts` listeners.

### 3.2 Endpoint: `getEventStats`

- **Module:** `functions/src/admin/eventStats.cjs`, `createGetEventStatsHandler({ db, auth, getConfig, now, log })`, with `buildHandlers` copied from `systemErrorsAdmin.cjs`. Re-export in `functions/index.js`; add the name to `.github/smoke-endpoints.json`.
- **Method and tier:** POST only, else `methodNotAllowed`. **Tier: staff**, stated at the call: `requireAdmin({ auth, getConfig }, req, { tier: 'staff' })`, before any read.
- **Request:** the body is ignored.
- **Queries:** 30 `count()` aggregates in one `Promise.all`, each a whole collection or one `==` filter, so single-field indexes serve them and `firestore.indexes.json` does not change. Users: total plus 4 statuses, plus `profileComplete == true`. Tickets: total plus 4. Speakers: total plus 5. Content: 6 collections × (live `visible == true`, draft `status == 'dirty'`). Errors: `resolved == false`.
- **Status keys come from the shared constants** in section 2.
- **Response 200:**

```json
{ "readAt": "<ISO>",
  "registrations": { "total": 0, "byStatus": { "pending": 0, "ticketed": 0, "approved": 0, "revoked": 0 }, "profileComplete": 0 },
  "tickets": { "total": 0, "byStatus": { "valid": 0, "refunded": 0, "cancelled": 0, "pending_info": 0 } },
  "speakers": { "total": 0, "byStatus": { "draft": 0, "invited": 0, "accepted": 0, "approved": 0, "removed": 0 } },
  "content": { "cmsPages": { "published": 0, "drafts": 0 }, "…": "one entry per PUBLISHABLE_COLLECTIONS name" },
  "errors": { "unresolved": 0 },
  "funnel": [ { "id": "accounts", "count": 0 }, { "id": "ticketed-or-approved", "count": 0 }, { "id": "approved", "count": 0 } ] }
```

- **Funnel** (#181 adds it): `accounts` is `registrations.total` (revoked included). `ticketed-or-approved` is `ticketed + approved`, summed on the server. The stages nest, because an admin can approve a `pending` account directly (`registration.cjs` `TRANSITIONS`).
- **Failures:** any aggregate failure is logged and answers 500 through `internal(res, 'The event figures are not available right now. Try again.')`. Never part of the figures.
- **Limits:** a fixed 30 aggregates per call. No paging, no cache, no polling. The client calls on mount and on Refresh only.
- **`admin_logs`:** none. A read of counts, like `listSystemErrors`.

### 3.3 Rules changes

None. `config/event` stays client-read-only. `tickets` and `system_errors` stay closed to every client; `users` and `speakers` stay admin read. The overview reads none of the four in the browser. `sessionBookmarks` stays public read.

## 4. Security and privacy

- **PII leaving the deployment:** none new. `getEventStats` returns integers and a timestamp. A test pins every key path.
- **Public data:** milestones and the goal become public (`config/event` is public read and bundled). The editor hint says so.
- **What the rules enforce (unchanged):** no client writes `config/*`; the collections behind the counts stay closed to non-admins; the overview never reads `users` in the browser.
- **Non-admin:** `getEventStats` answers 401 without a token and 403 for a non-admin or an unverified email. No query runs before the gate. Milestones and bookmark counts stay public by design.
- **Staff:** calls `getEventStats` and sees the overview, milestones, and popularity. Staff see the unresolved error count only, never the operator-only rows. Staff may save milestones (the Event page and `updateEventConfig` are staff on a4). Gap: the form always sends `sender`, which a4 refuses for staff, so a staff save of the page fails on a4's base. b1 does not change sender handling; its report names this for the director as an a4 follow-up. Operators are unaffected.
- **Abuse cases:** Refresh costs at most 30 aggregates per press, admin only, no polling. Labels render as React text, capped at 20 entries and 80 characters. The goal is range checked. Counts cannot be inflated past the `bookmarkSession` gate (attendee access, one membership per account).

## 9. Decisions and open questions

**Decisions the builder may not change without the director:**

1. **One staff-tier endpoint of `count()` aggregates.** All figures or none, no `admin_logs` row, no cache. It meets "server aggregate" with no document bodies read.
2. **"On the site" is live `visible == true`; "Unpublished changes" is draft `status == 'dirty'`.** The `listDirty` predicate, so the #197 banner cannot disagree.
3. **Funnel: Accounts, then Ticketed or approved, then Approved, with Revoked stated beside it,** summed on the server. The only nested stages the status machine gives.
4. **`config/event.milestones` `{ label, date }` and `registration.goal`,** compared with the approved count. The plan's store; approved grants attendee access.
5. **Milestones are edited at the Event page's tier (staff on a4).** No per-field tier split.
