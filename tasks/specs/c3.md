## 3. Design

### 3.1 Data model

- No new collection. `cmsTimeline/{id}` and its draft. Who writes: staff or operator through the generic endpoints; `cmsPublish`; the demo seed. Who reads: anyone, live and `visible == true`; either admin tier, both revisions.
- Fields, checked on the merged result at save:

| Field | Stored | Rule | Editor control |
|---|---|---|---|
| `year` | integer | required; 1900 to 2100 | Year |
| `title` | string | required; trimmed; 1 to 120 characters; no control character | Title |
| `description` | string or null | trimmed; blank is null; at most 600; no control character except a line break | Description |
| `seeded`, `seededAt` | boolean, string | kept for the re-seed rule | not shown; cleared on save |

- **Other keys.** A key the request sends outside this set is refused: `<key>: unknown field`. A key outside the set that only the stored draft or live doc carries (the generic endpoint has accepted any key until now) is dropped from the merged result, so the next save cleans the entry instead of locking it. The live doc is public and ships in the snapshot, so no stray key survives a save.
- Ids: the editor mints `crypto.randomUUID()`. The generic `isValidDocId` rule applies.

### 3.2 Endpoints

No new endpoint. **Tier: staff** for `cmsCreateContent`, `cmsUpdateContent`, `cmsDeleteContent`, `cmsPublish`, as a4 states them. c3 adds no gate.

- **New module `functions/src/cms/timeline.cjs`:** `TIMELINE_FIELDS` (`year`, `title`, `description`, `seeded`, `seededAt`), `TIMELINE_LIMITS` `{ yearMin: 1900, yearMax: 2100, titleMax: 120, descriptionMax: 600 }` and `validateTimelineFields(fields, sent)` returning `{ ok: true, fields }` normalized or `{ ok: false, errors }`. `sent` is the request's own field map; unknown keys in it are refused, unknown keys only in `fields` are dropped. Messages name the field: `year: enter a year from 1900 to 2100 as four digits`, `title: must be text`, `title: enter a title`, `title: use 120 characters or fewer on one line`, `description: must be text`, `description: use 600 characters or fewer`. Pure; no requires. Test for control characters with `/\p{Cc}/u` (lint rejects `\u0000` ranges).
- **Seam in `content.cjs`:** `checkTimelineFields({ collection, fields, sent })`, a no-op outside `cmsTimeline`, called in both transactions after `checkBlockContract` (and after c2's organization seam when it is on the tip), with `sent` = `checked.fields`. Its normalized fields are what `checkSessionStructure` receives (a no-op outside `cmsSchedule`), so they reach `writeDraft` through `structure.fields`. A refusal throws `RequestError(400, 'bad-request', errors.join('; '))`, so nothing is written and no log row is made.
- **Requests.** Create `{ collection: 'cmsTimeline', docId, fields: { year, title, description }, visible }`. Update the same, plus `seeded` and `seededAt` set to `DELETE_FIELD_SENTINEL`. Both answer `{ docPath, docId, status: 'dirty' }`. Delete `{ collection: 'cmsTimeline', docId }` answers `{ deleted: [live, draft] }`. Publish `{ collection: 'cmsTimeline', docIds }`.
- **Limits:** the caps above; `cmsPublish`'s 2000 ids. **`admin_logs`:** the existing rows on `cmsTimeline_drafts/<id>`, `cmsTimeline/<id>`, and the queue row.

## 4. Security and privacy

- **Rules enforce** (unchanged): anonymous and non-admin clients read live entries with `visible == true` only; drafts are readable by either admin tier only; no client writes anything.
- **On write:** type, range, length, one-line title, no unknown key sent, stray stored keys dropped, trimmed text, blank description to null, all inside the write transaction. No HTML is accepted as markup; the fields are plain text.
- **On read:** `prepareTimelineDocs` drops malformed and hidden docs before any render, so a script-written doc cannot blank the home page. React renders title, year, and description as text; no `dangerouslySetInnerHTML`, no stored value becomes an `href`. The section's own `richtext` blocks keep `sanitizeHtml` through `SectionBlocks`.
- **Non-admin:** no `/admin` (`AdminGate`), 401 or 403 from every endpoint before any read, no draft read. **Staff:** list, create, edit, publish and delete entries. Staff cannot read `admin_logs` (operator on a4). **Operator:** the same as staff here.
- **PII:** none. No text from strangers, so no feature flag and no rate limit.

## 9. Decisions and open questions

**Decisions the builder may not change without the director:**

1. **Add a timeline snapshot module.** None exists, so "the snapshot still renders on first paint" cannot hold without one. It follows the organizations pattern end to end.
2. **No new endpoint and no rules change.** The generic endpoints already write `cmsTimeline`; a seam in `functions/src/cms/timeline.cjs` adds the type checks, like c2's.
3. **The field set is year, title, description; unknown keys sent are refused and stray stored keys are dropped.** The live doc is public and ships in the bundle. No link field and no image.
4. **Oldest first, by year, then title, then id.** A history reads forward. No counter; the year is the only number.
5. **The renderer is the home page's `history` section, drawn through `renderSection`,** with its blocks first and the list under them, at the page's own arrangement. No new block type or page, so the operator's order, slot, and delete still work.
6. **Page tier staff; "Timeline" in the Content group; lazy routes; create at `timeline/new/entry`.**
7. **The browser mints the id once per form, and a create that succeeded turns later attempts into updates.** A retry cannot make a duplicate or a 409.
8. **A galley list, not a ruled table.** There is nothing to compare across columns.
9. **Saving clears `seeded` and `seededAt`,** so a re-seed skips an edited entry (`scripts/lib/idempotency.cjs`).
10. **Admin vocabulary in the admin; a3's `Timeline` unchanged on the site.** Dispatch from a tip with a3 and a4.
11. **No draft preview in the editor.** `/?preview=1` is a landing path that `ProfileSetupRedirect` can send to `/profile`; changing that component is outside #194.

**Open questions, each with the default the builder takes:**

- Newest first instead? Default: oldest first.
- A link per entry to a recap page? Default: no.
- Placeholder entries in `seed.cjs` for a real deployment? Default: none.
- The History section on the recap page too? Default: no.
- A draft preview once `ProfileSetupRedirect` spares `?preview=1`? Default: not in c3.
- If the E2E hold case (§5, case a) is not deterministic on CI: default to keeping `HomeHistory.test.jsx` case 1 as the proof and say so in the report.
