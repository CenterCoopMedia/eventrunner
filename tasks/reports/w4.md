# w4 report: issue #328, safe template workflow for repeat events

## What changed

- `scripts/export-event-template.cjs` (new). This script reads the past event's project. It never writes to that project. With `--dry-run` it prints the inventory and writes no file. `--out <file>` writes the template JSON and refuses a file that already exists. `--page <id>` can be given more than one time, and it limits the export to the pages you name.
- `scripts/lib/event-template.cjs` (new). This file holds the allowlist, the export, the inventory text, the parser that checks the template again at apply time, the merge of answers, pages and content, the apply gate, and the readiness row named "Template reuse".
- `scripts/init-event.cjs`: added `--template <file>`. The apply refuses each of these cases and writes nothing:
  - the target is the source project
  - the target is not empty (`config`, CMS pages and content with their drafts, `users`, `tickets`, `session_pitches`)
  - `--force` is given
  - the answers file has no dates, or it reuses a date of the source event
  - the answers file has no `owner` with a name and an email, or the owner is not an operator
  The apply writes `config/template` (source, owner, source dates). It prints the inventory and the instruction to confirm billing, sender and providers. `--check` adds the "Template reuse" row.
- `scripts/lib/answers.cjs`: the answers file accepts `owner: { name, email }`.
- `scripts/lib/write.cjs`: `readConfig` also reads `config/template`.
- Docs:
  - `docs/CLIENT_ONBOARDING.md`: new section "Reuse a past event as a template". It covers what is carried and what is not, the steps, accounts across separate events, and export and archive of the past event.
  - `README.md`: the "Operating model" section.
  - `scripts/README.md`
  - `CHANGELOG.md`
- Tests:
  - `scripts/export-event-template.test.cjs`: 10 tests on an in-memory database.
  - `tests/event-template.rules.test.js`: 4 tests on the emulator with `demo-past-event` and `demo-next-event`.
  - `scripts/lib/event-template.fixtures.cjs`: synthetic fixtures that both test files share.

## Decisions the owner may want to change

1. The template has an allowlist of `config/event` fields: tagline, timezone, the legal operator and contact lines, social, SEO description, organizer and default OG path, and the registration action label. The template does not carry the name, dates, venue, tracks, registration window, sender, Auth or legal review.
2. The template does not carry logo files or any content block that names a stored file, as a path or as a download URL. The inventory lists them so the operator can copy them by hand. If a template block linked to a file in the source bucket, the new event would depend on the source project.
3. The template does not carry the legal pages or `email_templates`. Init seeds them again from the new project's providers.
4. Blocks that init builds from settings (CONFIG_SEEDS: the title, the dates, the venue) are built again from the new event's settings.
5. Each reused block keeps `seeded: true`, so `--check` counts it until an editor saves it. This is the review step. A large site can use `--seeded-threshold` during setup.
6. The template carries the feature switches, including public-intake switches such as pitches. The inventory shows them for review.
7. The owner must be one of the new event's operators. The owner is stored in `config/template`, not in `config/event`. This leaves `packages/shared` and the schema unchanged.
8. The "Template reuse" readiness row is added in the scripts layer, not in `shared/readiness`. For this reason the admin diagnostics page does not show it.
9. `docs/ROADMAP.md` does not list #328, so there was nothing to tick.
