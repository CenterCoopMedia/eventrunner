### Family 7: the tabs and the segmented control take an unavailable state

Decision: both take `disabled` per item, drawn as `aria-disabled="true"`, not
`disabled`. The item stays in the row and in the arrow-key ring so a reader
can land on it and hear why (`hint` is read as part of its name); its handler
refuses every activation path (click, Enter, Space, and arrow selection), the
arrow keys move on from the focused item rather than from the selected one,
and both test files prove the refusal. The specimen book draws the state on
both controls. The speaker session hub (issue 212) can therefore show a tab
for a panel that exists and cannot be opened yet; a tab with nothing behind
it at all is still not rendered.

## Decisions the owner may want to change

- The `when` card is a fact too, not a stat. A date range is a term and a
  description; the previous stat asked for a source line for the dates. The
  demo's evidence-bearing `info__when` stat is replaced by the fact.
- A second block type, `quote`, landed with the pull quote so the device has
  a content slot. Its fields are `text` and an optional `attribution`.
- `SessionState` no longer draws through `Tag`. The record asks for a word with
  an ink change and a rule, and a finished session in the back-issue ink; the
  tag's boxed ground could not carry the ink change.
- `ProfilePhoto` lost its `rounded-brand` utility: the avatar's corner is the
  `--avatar-radius` token so a style can move it (Zine, Broadsheet and Field
  Guide square it). The default is still the brand radius.
- The preset catalog mirrors (`presetCatalog.cjs`, `presetRemaps.cjs`,
  `presetCopy.js`, `presets/README.md`) are committed with the source change,
  not in the regenerate commit: they are not on the director's regenerate
  list and their freshness test fails without them.
- A live `config/theme` overlay now paints one fetch later than it did. The
  provider waits for the remaps chunk (27KB raw, fetched in parallel with the
  config document) before it writes the runtime overlay, so a visitor sees
  the build-time look for that long. The alternative was carrying every
  style's remaps in the chunk every visitor downloads, for an overlay most
  deployments never write. A deployment that publishes its theme rebuilds,
  and the rebuilt stylesheet carries the style, so the wait is for the gap
  between a publish and the next deploy.

## The bundle budget

The budget file (`scripts/ci/bundle-budget.json`: initial 1,080,000 raw and
292,000 gzip bytes) and the script are untouched. As first built, the wave
put the demo's initial chunk 7,622 raw bytes over. Most of the growth was the
preset catalog: with five option groups per style and the remaps every new
device needs, `presetCatalog.cjs` grew from 34.7KB to 60.2KB of source, and
all of it rode the chunk every visitor downloads, although a first paint
reads none of it (the generated stylesheet already carries the chosen style
with its picks resolved).

The catalog is now split by who needs it, on the director's route:

- `packages/shared/src/presetCatalog.cjs` (26.7KB of source, 14.9KB as data)
  keeps what every path reads: palettes, type maps, shape, motif default and
  each option group's default and choice ids. The config validator, the
  contrast check and the palette resolver in Cloud Functions read nothing
  else, so the functions bundle is unchanged in behaviour.
- `packages/shared/src/presetRemaps.cjs` (43.2KB of source, 27.4KB as data)
  carries what a style moves: its own token and component-font remaps, what
  each choice moves, and the component defaults a style change resets. It
  registers itself with the resolver when required. The web app loads it as
  its own lazy chunk (`apps/web/src/lib/presetRemaps.js`; 27,100 raw bytes
  in the demo, against a 180,000 lazy budget) on the paths that resolve a
  style at runtime: the provider's overlay effect waits for it before it
  writes `<style id="event-theme-runtime">`, so a live `config/theme` overlay
  still resolves a picked choice, in full or not at all; the admin chunk
  loads it alongside itself; the demo band prefetches it as it mounts so the
  first style switch lands as fast as the rest; the specimen book reaches it
  through the provider. Node callers reach it through
  `scripts/lib/shared-theme.cjs`, which requires it once, and the web test
  setup registers it for every test.
- `resolvePresetTokens`, `resolveComponentFonts` and `pickedChoices` read the
  registry and throw, naming the module, if asked before it is loaded, so a
  style is never half-resolved. A document that names no style resolves
  without it. `getPreset(id)` no longer carries `tokens` or `componentFonts`;
  the tests that read them read `PRESET_REMAPS.presets[id]` instead.
  `scripts/build-preset-catalog.test.cjs` checks that the two halves name
  the same styles and choices and that the component defaults cover exactly
  the tokens some style or choice moves.

## The adversarial review (2026-09-23)

Thirteen findings on the branch at 77e136d, each fixed test-first. Each
clause below is quoted from the finding and paired with the test that proves
it on the surface the finding names.

### Major

**1. "RuledTable's HorizontalScrollRegion has no overflow of its own ... a
wide table spills and the page scrolls sideways."** `RuledTable` now passes
`overflow-x-auto` to the region itself, joined with the caller's className
(`apps/web/src/components/editorial/RuledTable.jsx`). "Either bound the
region's block size ... or drop the sticky-head claim": dropped. The region
is the scroll container, and a head pinned inside a container that scrolls
only sideways pins to nothing the reader scrolls; pinning it would mean a
bounded region and a table scrolling inside a box, which is a widget this
system does not draw, and the site's tables are short. `position: sticky`
left `.ruled-table thead th` (`apps/web/src/index.css`); the claim left the
`table` contract note, the component comment, the specimen note
(`EditorialSection.jsx`), the CHANGELOG and `docs/design-reference.md`.
The design record (`docs/plans/2026-09-10-design-vocabulary-expansion.md`
§3.1) still says "sticky head"; the record is the director's, so it is
noted here rather than edited. Tests: `RuledTable.test.jsx` "gives the
region its own overflow" (the class on the region, with and without a
caller className) and "claims no sticky head" (reads the stylesheet rule).

**2. "The seed upgrade path (#234) states the venue twice on any launched
site."** Reproduced with the repo's own fakes before the fix
(`scripts/lib/write.test.cjs`, "upgrading a launched site"). A
`REPLACED_CONTENT_IDS` map in `scripts/lib/seed.cjs` (`info__where`
replaces `info__where_venue` and `info__where_address`; `info__who` and
`info__when` replace nothing, and the map's comment says why). A new
`withholdUpgradeSeeds` in `scripts/lib/write.cjs`, run by `init-event.cjs`
before `seedCollection`, withholds a replacement while any predecessor
survives as the client's (in either revision, through the same
`decideSeedWrite` every seed write uses) and reports it as a kept item;
the predecessors of a withheld replacement are kept out of the obsolete
removal too, so a client who edited only the venue line does not lose the
still-seeded address line beside it. "Do not publish a new '[Replace]'
placeholder onto a launched home page": a placeholder is not created at
all when its section already holds a client-edited block, because an
unpublished draft would be a block the operator never wrote, waiting to
ride the next publish, and the operator can add the fact from the palette.
Tests: `write.test.cjs` "upgrading a site whose venue lines are still the
seed's replaces them with the fact, cleanly" (predecessors still seeded:
`info__where` and `info__who` created, both predecessors removed, the stat
refreshed to a fact), "upgrading a launched site keeps the client's venue
lines and creates neither the duplicate fact nor a new placeholder"
(predecessors client-edited: both withheld with the predecessor named,
nothing created, nothing removed, no draft), the draft-revision case, the
pass-through of existing documents and the fresh-site case;
`seed.test.cjs` checks the map names seeded replacements and obsolete
predecessors only.

## The adversarial review, round 2 (2026-09-24)

Eighteen of twenty-three findings confirmed; all eighteen fixed test-first
on the stack base (`trial/a3-on-tiers`: PR 269's tip with the tier 2 token
moves and the admin tiers, plus the director's two commits). Each fix is one
commit, and each test named below failed before its fix, on the surface the
finding names.

**A (blocker). "The CMS never clears `seeded`."** Confirmed with the
reviewers' probes. Root cause: `cmsUpdateContent` merged an edit onto the
stored fields, flag included, and `publishDocs` copied it live; the page
validator refuses the field, so pages were never affected (a test now
holds that). Fix at the source: `cmsUpdateContent` and `cmsCreateContent`
drop `seeded` and `seededAt` from the merged fields
(`functions/src/cms/content.cjs`). Backstop for deployments already live:
one shared rule, `shared/seed` (`SEED_ACTOR`, `isSeedOwned`,
`publicContentDoc`): a document is the seed's only while it is flagged AND
its recorded writer (`publishedBy` on a live doc, `updatedBy` on a draft)
is the seed actor or nobody; an operator's uid or email makes it the
client's whatever the flag says. `decideSeedWrite` applies it to both
revisions (so `withholdUpgradeSeeds` and `removeObsoleteSeeds` do too), and
every boundary the public site reads through hands the page the public
shape: the committed snapshot (`scripts/lib/emit.cjs`), the public content
endpoint (`getSiteContent`) and the live listener
(`contexts/ContentContext.jsx`), each dropping the publisher. Home's live
When rule therefore reads `seeded`, which an admin save now provably
changes and which the public data corrects for old sites. Tests that failed
