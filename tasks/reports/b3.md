## Departures from the spec

1. **Audit detail fields sit under `details`.** The export row is `{ action, docPath, uid, email, at,
   details: { rowCount, filter } }`, and a resumed delete adds `details: { resumed: true }`. The spec
   put them at the top level. The base's `logAdminAction` (a4) makes `details` the one optional field
   for what a row would otherwise not say, so readers keep the fixed five-field shape.
2. **Formula escaping also covers leading whitespace.** A cell whose first non-whitespace character
   is `=`, `+`, `-`, or `@` gains the apostrophe too (the spec said "starts with"). Some spreadsheet
   imports trim leading spaces. Stricter only.
3. **`AdminApp.jsx` is edited** (the spec said not). With the export and the panel, the admin entry
   chunk reached 50,723 bytes gzip, over the 50,000 lazy-chunk ceiling in
   `scripts/ci/bundle-budget.json`. The attendees route now loads lazily, the same way Event settings
   does. The entry chunk is 48.06 kB gzip, and the page chunk 4.10 kB.
4. **The sweep reads a page at a time** (`orderBy('__name__').limit(n)` and `getFiles({ maxResults,
   autoPaginate: false })`). The owner can create notes and photo files without limit, and one read
   of all of them could exhaust the function's memory. The spec's chunk sizes (200, 400) are kept.
5. **E2E added** (the spec said none), because the brief asks for proof on the real surface.
6. Small additions: the self guard also compares the sign-in address; refusal codes are
   `own-account`, `admin-account`, `speaker-linked`, `too-many-claims`; a released ticket also gets
   `updatedAt`; a counter is written only when its document exists; a refused delete (409) is stated
   in the panel with focus, while `delete-incomplete` goes to page level; the incomplete notice puts
   the account name before the server's words; a 404 on a retry counts as done.
7. **Review round.** Any delete failure that may follow the directory commit is kept on the page
   with the retry, not only `delete-incomplete`, and every sweep releases ticket claims again (the
   spec released them in phase 1 only).

  the deleted person's address; 10,000 rows per export; status and visibility as stored values; no
  bulk delete.

## Left undone and residual risk

- An ID token stays valid for up to one hour after the sign-in is deleted. In that window the
  session can still write its own `sessionNotes`, upload a profile photo (both rules check only the
  uid), or claim a ticket through `ticketingVerifyOrder`. A retried delete clears all three since
  the review round, but nothing retries it by itself: the admin has to run it again. A rules change
  or a revocation check is out of scope.
- The lockfile integrity hashes for the shared package differ after `npm install` in this worktree.
  No `packages/shared` file changed, so they are not committed; both lockfiles were restored to the
  committed text before the final checks.
- The regenerate commit also carries `docs/docs` pages from a4's Markdown (client onboarding, deploy
  runbook, WebMCP diagnostics), because the base holds a4's Markdown without its dropped regenerate
  commit.
