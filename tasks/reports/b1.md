## Issue #178: server-side event statistics endpoint

staff tier. It runs 30 Firestore `count()` aggregates in one `Promise.all`: users (total, one per
`REGISTRATION_STATUSES`, `profileComplete == true`), tickets (total, one per `TICKET_STATUSES`),
speakers (total, one per `SPEAKER_STATUSES`), each of the six `PUBLISHABLE_COLLECTIONS` (live
`visible == true`, draft `status == 'dirty'`), and `system_errors` (`resolved == false`). It reads
no document body. Each query is a whole collection or one `==` filter, so
`firestore.indexes.json` does not change. The gate runs before any aggregate. A failed aggregate
answers 500 with no figures. The endpoint writes no `admin_logs` row. The test fake gains `count()`
(`functions/src/cms/firestoreFake.cjs`).

## Where the build departs from the spec

1. **`requireAdmin` is called with `db`.** The spec writes `requireAdmin({ auth, getConfig }, …)`.
   On this base every call passes `db` so the gate reads `config/bootstrap` live and fails closed
   (a4 finding 7), so this one does too. The refusal tests still prove no `count()` runs before the
   gate.
2. **The milestone limits are exported, and `schema.mjs` and `config/index.mjs` are edited.** The
   spec kept `schema.mjs` untouched to avoid a clash with a2, which is now in the base. The editor
   needs the cap (20) and the label length (80); exporting `MILESTONE_KEYS`, `MAX_MILESTONES`,
   `MAX_MILESTONE_LABEL_LENGTH`, and `MAX_REGISTRATION_GOAL` keeps one definition for the form and
   the server.
3. **The goal field is `type="text"` with `inputMode="numeric"`, not `type="number"`.** A number
   field reads an entry it cannot parse as `''`, which the form sends as `null`, which clears the
   stored goal. That is the silent clear the spec's own "never NaN" rule exists to stop. A text
   field keeps the entry, so a non-number goes as typed and the server names it.
4. **Milestone rows are also checked at submit**, the way the social accounts are (#219): a blank
   name or a missing date marks the field, takes focus, and sends nothing. A server refusal
   (`milestones[0].date: …`) marks the same field through `errorFor`, but on this page every server
   rejection moves focus to the `ServerErrorSummary`, not to the field; the spec's
   "`focusFirstError`" for server errors does not match the page, and I kept the page's rule.
5. **The staff `sender` gap is not reported**: a4 fixed it. Staff saves of milestones and the goal
   are tested on the server and on the page.

## Decisions the owner may want to change

- `TIER_SCOPE.staff` is derived from the docket, so it now starts with "Overview": the refusal page
  and the Access page say "Staff run Overview, Pages, Sessions, …". `docs/ADMIN_GUIDE.md`'s tier
  table says the same.
- Overview panel order: Event figures, Milestones, Registration funnel, Content readiness. The
  Milestones panel reads config/event, so it shows even when the figures fail.
- The funnel's revoked sentence is shown only when there is a revoked account; the first figure
  sentence already states "0 revoked".
- "Unpublished changes" counts every dirty draft, including a record never published (the
  `listDirty` predicate the spec fixed). The admin guide says so.
- A session with saves stays on the Most saved list after it is hidden; `unsaved` counts only
  sessions on the site.
- Milestone dates use `formatDayDate`, which has no year; the "In N days" phrase disambiguates.
- The overview's figure primitives and panels live in `apps/web/src/admin/overview/`.
- **Bundle headroom for the other builders.** The admin entry chunk (`AdminApp-*.js`) is 173,742
  raw and 49,145 gzip bytes here against a lazy-chunk budget of 180,000 and 50,000; on the base it
  is 173,347 and 49,011. This branch adds 395 raw and 134 gzip bytes to it (the overview itself is a
  separate 8.3 kB chunk). b2 and b3 also add routes to that chunk, and the stack may cross the gzip
  ceiling; making their pages lazy keeps it under.
