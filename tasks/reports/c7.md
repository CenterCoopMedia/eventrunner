## Departures from the spec

1. **The link's name is an `aria-label`**, "Edit section: <label>", not a visible "Edit section"
   plus an `sr-only` ": <label>" span. jsdom's name computation puts a space before the inline span
   ("Edit section : Details"), so one element had two names, one in tests and one in Chrome. The
   label starts with the visible words, so a voice command still finds it.
2. **`SectionEditLink` takes an optional `className`.** The hero link and the link after an
   `sr-only` section pass `mt-sm`, so no wrapper element renders empty for a visitor.
3. **The first heading reads "Welcome to the admin panel".** `docs/COPY_STYLE.md` names the
   interface "admin panel". The rest of the copy is the spec's.
4. **The panel's classes live in one `.admin-tour` rule in `index.css`**: the panel ground and rule
   through `@apply`, and a bottom margin of twice the stone's block padding. The title band
   (`.admin-job-line`) pulls itself up by the stone's top padding (c5's placement note), so inside
   the stone it would slide over the tour's foot; with the margin it lands one padding below the
   tour. The E2E compares the bounding boxes. The one rule also serves the failure line.
5. **The shell's tour state is a run number**: null while closed, 0 on a first visit (no focus),
   and one more for each Take the tour (the panel remounts at step 1 and focuses its heading).
   Fewer bytes than an object in the entry chunk; same behaviour.
6. **The failure case has its own test file**, `AdminLayout.tourFailure.test.jsx`. A module mock
   that makes the tour import reject applies to a whole file, and `React.lazy` keeps its first
   answer, so it cannot share a file with the cases where the tour loads.
7. **The keyboard unit test uses a small Tab helper.** The repository has no `user-event`, and I
   did not add a dependency. The helper moves the focus to the next control in document order and
   turns Enter on a native button into a click, as a browser does. The E2E is the real keyboard
   proof.
8. **`listWords` is exported from `AdminLayout.jsx`** (one word), so the tour's "A, B and C"
   matches `TIER_SCOPE`'s.
9. **The admin entry chunk grew by 1,071 raw and 387 to 401 gzip bytes**, over the spec's caps of
   1,000 and 350. The spec set those caps for about 1,073 gzip bytes of headroom; on this base the
   chunk has 13,991 (the pages are deferred now). The spec's own required parts account for it:
   the failure line alone is 238 raw and 54 gzip bytes, and the lazy import with its preload entry
   and the Suspense boundary are about 270 raw. The rest is the stored flag, the state and the
   button. No ceiling was raised, and every chunk is inside its budget. The public caps hold (863
   raw, 214 and 268 gzip against 1,000 and 400).

## Decisions the owner may want to change

- **A staff admin cannot open a section whose id decodes to a slash.** a4's `sectionTier` fails
  closed on any segment that decodes to `/`, so `/admin/content/home/a%20b%2Fc` meets the tier
  refusal for staff (an operator gets the editor, as the `AdminContent` test shows). No drawn
  section can reach this: a section is drawn only with blocks, and a block's section id must match
  `SECTION_FIELD_RE` (letters, digits, `_`, `-`); the three sections Home draws itself are fixed
  ids. I left a4's security rule alone.
- End tour on the failure line stores the end, like End tour on the tour.
- The tour opens once per account per browser for both tiers, and names only the groups the tier
  reaches. It has no route and no docket item.
- The Sponsors link on the home page opens the line above the wall; the wall is edited under
  Organizations (the admin guide says so). The `venue_map` section opens its content section (the
  spec's open question 1 default). A system page's core has no link (open question 5).
- The dismissal stays in the browser; it does not follow the account (open question 3).
