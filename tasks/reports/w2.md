## #356 Eventbrite webhooks require unprovisioned HMAC

Commit: "Authenticate Eventbrite webhooks with a URL secret, not an HMAC".

What changed:

- `eventbrite.cjs`: no HMAC check. `registerWebhook` registers
  `<callbackUrl>?token=<TICKETING_WEBHOOK_SECRET>` (https only).
  `verifyWebhook(rawBody, headers, { query })` compares `query.token` with the
  secret through `safeEqual` (SHA-256 digests and `timingSafeEqual`). A missing,
  empty, repeated, or wrong value gives `invalid_secret` before the body is
  read. The secret must be at least 32 characters; the error never prints it.
  `api_url` must be https on `www.eventbriteapi.com` with no port or
  credentials and the `/v3/events/{e}/orders/{o}/` path. Nothing fetches the
  delivered URL; the drain fetches `/orders/{id}/` from the fixed `API_BASE`, and
  `sync.cjs` already drops an order for another event. API error messages are
  redacted (raw and URL-encoded secret). A subscription at the bare endpoint
  (old registration, no secret) is reported as stale.
- `functions/src/ticketing/webhook.cjs`: passes `{ query: req.query || {} }` as
  the third argument to `verifyWebhook`. Stripe ignores it; Stripe behaviour is
  unchanged. Still one queue, `ticket_sync_queue`.
- Docs: `functions/README.md` (new "Eventbrite webhooks" section),
  `docs/EVENTBRITE_VERIFICATION.md` (judgment call 1 rewritten as a sandbox
  check), `docs/CLIENT_ONBOARDING.md`, `docs/DEPLOY_RUNBOOK.md`, `.env.example`,
  `scripts/lib/checklist.cjs`, `CHANGELOG.md`, fixtures README, provider
  `index.cjs` comment.

Criteria, each with its test:

- "The Eventbrite provider still requires TICKETING_WEBHOOK_SECRET and rejects a
  delivery without the HMAC header." The secret is still required, but now as
  the URL secret Eventbrite can carry. Tests in `eventbrite.test.cjs`: "a
  delivery with no signature header and the URL secret is valid", "an HMAC
  header alone no longer authenticates", "missing URL secret → invalid", "wrong
  URL secret → invalid_secret", "a secret of the right length but wrong bytes
  refuses", "the comparison is constant-time — it goes through safeEqual",
  "construction refuses a short URL secret, and the error never prints it". On
  the real handler surface, `eventbriteEndToEnd.test.cjs`: the order.placed and
  refund runs (no signature header, secret in `req.query`) give 200 and
  enqueue, and "a delivery with a missing or wrong URL secret never reaches the
  transaction" gives the generic 401 and writes nothing.
  `webhook.test.cjs` "the handler passes the delivery URL query to
  verifyWebhook".
- "registerWebhook still sends only endpoint_url, actions, and event_id." Those
  are the only fields Eventbrite takes, so the secret now rides in
  `endpoint_url`. Test: "registerWebhook: no existing subscription → creates one
  whose endpoint carries the URL secret", which also feeds the registered URL's
  query back to `verifyWebhook` and gets `valid: true`. "a subscription at the
  bare endpoint (no URL secret) is stale, not reused".
- "the file still says classic signing is unverified." The module doc's
  judgment call 1 now describes the URL secret, and states that #79 must confirm

- No SSRF: "api_url must name Eventbrite's own API host over https" (nine
  refused hosts and forms), "makes no network call", and the end-to-end "a

- No secret in logs: "an API error that echoes the endpoint never carries the

Met in code and offline tests. Not met: confirmation against Eventbrite. Whether

## Decisions the owner may want to change

1. Query parameter (`?token=`), not Basic auth in the URL userinfo as Postmark
   uses. A query string works with any sender that POSTs to the exact URL;
   userinfo depends on Eventbrite turning it into an `Authorization` header,
   which is unknown. Cost: Cloud Run request logs record the query string, so
   anyone with project request-log access can read the secret. Our code never
   logs it. Documented in `functions/README.md` and the verification runbook,
   with rotation steps. If the sandbox shows Eventbrite honours userinfo,
   switching is a small change.
2. Minimum secret length of 32 characters, enforced at provider construction.
   A deployment with a shorter `TICKETING_WEBHOOK_SECRET` fails to build the
   Eventbrite provider until the operator replaces it. Before this change no
   real delivery could pass anyway.
3. The HMAC path is removed, not kept as an alternative. Eventbrite has no way
   to send it, and two paths double the surface.
4. Stale subscriptions are reported, not deleted. The script prints their ids;
   the operator deletes them in Eventbrite.
5. `registerWebhook` ignores a narrower `events` list instead of throwing.
6. The script prints "(provider default)" when a provider declares no
   `webhookEventTypes`, instead of keeping a fallback list of its own.
7. `docs/ROADMAP.md` has no line for #356 or #357, so nothing was ticked.
8. Operators must run `register-ticketing-webhook.cjs` again after deploy, and
   delete the old webhook it names. The CHANGELOG entry says so.
