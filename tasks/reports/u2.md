# u2: Firebase CLI upgrade

## Result

`firebase-tools` moves from 14.27.0 to 15.22.4. It is held at `~15.22.4`, not at
15.34.0, the newest 15.x release. A 15.34.0 commit is kept on the local branch
`joe/wave3-u2-firebase-tools-15.34` for the director.

## Why not 15.34.0

From 15.23.0, `lib/apiv2.js` sends every request through
`new undici.ProxyAgent({ uri: HTTPS_PROXY })`. It ignores `NO_PROXY`. Before 15.23.0,
it used `proxy-agent`, which reads `NO_PROXY`. So on a machine with `HTTPS_PROXY` set,
emulator-internal calls to `127.0.0.1` go to the proxy.

The Storage emulator reads Firestore through that client for `firestore.exists()`.
The read fails, the rule reads "no document", and the owner is denied. On 15.34.0
in this container, `npm run test:rules` fails 5 of 44 tests in
`tests/storage.rules.test.js` (every `profile-photos/{uid}` owner write and delete).
The 311 Firestore and 17 session-pitch tests pass.

Proof without a change to the proxy settings: a local HTTP server on `127.0.0.1` and a
call through `apiv2.Client`. 15.34.0 returns the proxy's "refusing to tunnel" body.
15.22.4 reaches the server directly.

I could not run the suite on 15.34.0 with the proxy removed. The container rules forbid
an unset `HTTPS_PROXY`, and the permission check refused a loopback-aware chained proxy.
GitHub-hosted runners set no proxy, so CI would likely pass on 15.34.0. A developer
behind a corporate proxy would see the same 5 failures, and maybe broken functions
emulator calls too.

## Release-note review (14 to 15)

- 15.0.0: emulators need Java 21. CI (`actions/setup-java` 21), CONTRIBUTING, and the
  video docs already say Java 21. No change.
- 15.0.0: strict function timeout validation. Every `timeoutSeconds` is 540, inside the
  v1, v2 event, and HTTP limits. No change.
- 15.0.0: `.bolt` rules, `--open-sesame`, `firestore:backups:list --json` shape,
  Data Connect flags, `cli.auth.upload`. None is used here.
- Node: 15.x needs Node 20 or later. The repo and functions use Node 22. The functions
  emulator runs `engines.node` "22". No change.
- `firebase.json`, `.firebaserc` (absent; the deploy writes one per run with
  `target:apply`), `scripts/dev/run-e2e.sh`, `.github/workflows/deploy*.yml`,
  `scripts/deploy-functions.cjs`, `scripts/publish-site.cjs`, `docs/CLIENT_ONBOARDING.md`:
  every command and flag still exists (`deploy --only ... --non-interactive [--force]`,
  `target:apply`, `emulators:exec`, `hosting:clone`). No change.
- `scripts/deploy-functions.cjs` imports `lib/requireAuth.js` and
  `lib/deploy/functions/backend.js`. Both exports and `context.unreachableRegions` keep
  their shape in 15.22.4 and 15.34.0.
- `scripts/firebase-functions-prompts.test.cjs` pins the `--force` behaviour. It passes
  unchanged on 15.22.4. On 15.34.0, `createDeploymentPlan` is async and returns
  `{ regionalChangesets, ... }`; the side-branch commit updates the test for that.

## Side effect on the shared machine

The emulators share `~/.cache/firebase/emulators`. 15.x downloaded
`cloud-firestore-emulator-v1.21.0.jar` (1.22.0 for 15.34.0) and deleted
`cloud-firestore-emulator-v1.19.8.jar`. A builder still on 14.27.0 downloads 1.19.8
again on its next emulator run. That works while the network is up.
