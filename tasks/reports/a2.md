## Decisions the owner may want to change

- The editor edits the optional `handle` as well as service and link. The issue says
  "platform name plus URL", but ADR 0001 defines `{ platform, handle, url }` and the
  footer prints the handle; leaving it out would have dropped stored handles on save.
- Links allow `http://` as well as `https://` (`safeUrlHref`), as for every other
  operator-typed outbound link. The registration URL stays https only.
- The email addresses in `legal` accept `''` as well as null, because init seeds `''`
  for an unanswered address.
- The hashtag stays unrendered. It moved into the Social accounts panel with a hint
  that the site and email do not show it. No one-line use was obvious.
- The demo fixture gains no handles. Demo links would point at `example.org`, which is a
  dead end for a visitor. The demo was regenerated anyway, as the lessons require for any
  `apps/web` or `packages/shared` change.
- The link field is `type="url"`, like the session recording link. In a browser, a
  value with no scheme hits the native validation bubble before the form's own check
  runs; a `javascript:` or `https:host` value reaches the form's message.
- The 40-character cap is declared in `schema.cjs` rather than required from
  `speaker.cjs`, so the speaker module does not join the public first-paint bundle. A
  test holds the two numbers equal.
- A deployment whose stored `legal` or `social` block already carries an unknown field
  will have every event settings save refused until that field is removed from the
  document. The admin cannot remove it, because the save is merge-then-validate. I know
  of no such field in any seed or fixture.
- `docs/ROADMAP.md` lists #226 and #231 only as plain numbers in the M7 follow-up
  line, with no checkbox, so there was nothing to tick. I left the line alone to avoid a
  conflict with builder a1, who closes other issues from the same line.
