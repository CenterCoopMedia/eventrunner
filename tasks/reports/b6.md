## #218: Raster app icons in the web manifest

What changed:

- New `scripts/lib/png.cjs` (`node:zlib` only). `encodePng` writes 8-bit RGBA, filter 0,
  deflate level 9, IHDR, IDAT, and IEND only. `decodePng(buffer, { maxSide = 4096 })`
  checks the signature and every chunk's length and CRC, and needs IHDR first and once.
  It reads IHDR, PLTE, tRNS, IDAT, and IEND, and joins every IDAT before it inflates. It
  skips every ancillary chunk, so an APNG gives its default image. It reads colour types
  0, 2, 4, and 6 at 8 bits and type 3 at 1, 2, 4, and 8 bits, and applies tRNS to types
  0, 2, and 3. It reverses filters 0 to 4. It refuses a side over `maxSide` before it
  inflates, and inflates with `maxOutputLength` set to the exact size IHDR implies. The
  reason codes are `not-png`, `damaged`, `unsupported`, and `too-large`.
  `resizeSquare` area-averages in premultiplied alpha.
- New `scripts/lib/app-icons.cjs`: `APP_ICON_SIZES`, `appIconPath`, `PLACEHOLDER_MARK`
  (the numbers of `mark.svg`, no hex), `renderPlaceholderIcon` (full bleed, ring and dot
  centred, 4 by 4 samples), `readPlaceholderIcons`, `markObjectUrl`, `iconsFromMark`
  (square, 512 to 4096), `resolveAppIcons` (timeout, `redirect: 'error'`, non-2xx
  refused, 5 MiB cap while the body streams), and `writeAppIcons`, which writes both
  files and logs one line. The reason copy is the spec's, word for word. The code fails
  soft: a fetch or decode problem ships the placeholder, and only a file write throws.
- New committed `apps/web/public/branding/app-icon-192.png` and `app-icon-512.png`, drawn
  by the new `scripts/dev/build-app-icons.mjs` (`--check` compares pixels). The scripts
  copy these bytes and never re-encode them.
- `scripts/lib/site-manifest.cjs`: `buildWebManifest({ event, theme, maskable = true })`
  lists exactly the two PNG icons, `any maskable` or `any`. The SVG entries are gone.
  `buildSiteArtifacts` takes and passes `maskable`. The fallback
  `apps/web/public/manifest.webmanifest` is the new neutral output.

## Where I departed from the spec

- `write-site-files.cjs` calls `writeAppIcons` after the specimen-route check, not before
  `buildSiteArtifacts`. The manifest is then built by `buildWebManifest` with the icons'
  `maskable`. Reason: a sitemap refused with exit 4 must write nothing, and a test now
  proves that. `publish-site.cjs` follows the spec's order exactly.
- `markObjectUrl` gives "not an uploaded file in the branding folder" for an upload path
  with an extension other than PNG, SVG, JPEG, or WebP (for example `.gif`), because the
  "SVG, JPEG, or WebP" reason would be false for it. Uploads cannot have that extension
  (`upload.cjs` forces it), so only a typed path reaches this case.
- `resolveAppIcons` also returns `mark` (the trimmed slot path) so that `writeAppIcons`
  can log it.
- `AdminBranding.test.jsx`: a1's #230 timeout has not landed on this stack. The new test
  passes `20_000` as its own timeout, the budget a1's uncommitted work sets for this
  file. It sits in the existing `publishing the theme` block and uses `renderBranding`.
