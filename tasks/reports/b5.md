## #189 Bulk material download and coverage tracking

**No signed URL.** The issue names short-lived signed URLs. This build does not use them. Signing
needs `signBlob` (`roles/iam.serviceAccountTokenCreator`), and a fresh client project does not grant
it to the runtime service account; `downloadSessionMaterial` already hit the same limit
(`materials/download.cjs` module doc). So the archive is built by the function and streamed through
it (spec decision 1). The intent of the plan's note holds: access is checked on the request, and no
link to a file is written to any document. The browser holds a local object URL for one tick. The
commit body and the CHANGELOG entry say the same.

## Departures from the spec

1. **E2E added** (the spec said none). The director asked for it as the real-surface proof.
2. **`AdminApp.jsx` edited**: the materials route loads lazily through `DeferredAdminPage` (spec §8
   said not without the director; the dispatch allowed it). The page chunk is 6.47 kB gzip; the admin
   entry chunk fell to 33.67 kB gzip.
3. **`requireAdmin` gets `db`** (`{ auth, db, getConfig }`). a4 made every admin gate read
   `config/bootstrap` live and fail closed through `db`; the spec's call left it out.
4. **Entry names also replace `<>:"|?*` and drop trailing dots and spaces.** yazl's
   `validateMetadataPath` throws "absolute path" on a name that starts like a drive letter, and a
   Firestore session id can be `c:talk`; Windows extractors refuse the other characters and silently
   drop trailing dots and spaces, which could merge two names after the repeat check.
5. **Link refusal wording**: "materialIds: m2 is a link. Only files go in an archive." The spec's
   "… is a link; only files …" would be cut in two by `fieldErrorsOf`, which splits on `'; '`.
6. **Size parsing**: only a whole number of bytes passes (a decimal string or a number).
   `Number('')` is 0, which "finite after `Number()`" would accept.
7. **Selection is read against the file rows on screen.** The spec drops ids that are no longer file
   rows after a load; this also drops a row that a review change filtered out, so an archive never
   holds a file the admin cannot see.
8. **Coverage day label** comes from the live `dayId` (`resolveDayLabel`), with the same fallbacks as
   the sessions list, since the title and speakers come from the live document too.

## Decisions the owner may want to change

- Sort words: Material "A to Z" / "Z to A", Session "Schedule order" / "Reverse schedule order",
  Changed "Newest first" / "Oldest first" (first press on Changed is newest first).
- The archive result line clears on any selection or filter change and on the next press. The two
  refusals before a request ("Select at least one file.", "An archive holds at most 50 files. 51 are
  selected.") are caution notices (`role="status"`).
- A speaker id with no record is listed as the id in the data face, with no link (there is no record
  to open). The speaker list is sorted by name and hidden when empty.
- "Read at" is the time the list response arrived, on the event clock with the zone name.
- `listAllSessionMaterials` also sends `Cache-Control: private, max-age=0, no-store`.
- Spec Q1 stands: `uploadSessionMaterial` still accepts any `storagePath`, and `downloadSessionMaterial`
  still streams it; only the archive checks the prefix. An issue is needed before #213.
