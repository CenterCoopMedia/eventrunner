## #189 Bulk material download and coverage tracking

**No signed URL.** The issue names short-lived signed URLs. This build does not use them. Signing
needs `signBlob` (`roles/iam.serviceAccountTokenCreator`), and a fresh client project does not grant
it to the runtime service account. `downloadSessionMaterial` already hit the same limit
(`materials/download.cjs` module doc). So the function builds the archive and streams it (spec
decision 1). The intent of the plan's note holds: Access is checked on the request, and no link to a
file is written to any document. The browser holds a local object URL for one tick. The commit body
and the CHANGELOG entry say the same.

**What changed.**

- `functions/src/materials/bulk.cjs` (new).
  - `listAllSessionMaterials` (POST, staff tier): `limit(2001)`, answers at most 2,000 rows with
    `truncated`, no `createdBy` or `createdAt`, `updatedAt` as epoch ms, `url` only on a link and
    `storagePath` only on a file.
  - `downloadSessionMaterialsArchive` (POST, staff tier, `timeoutSeconds: 540`). It validates
    `materialIds` (array, 1 to 50, no repeat, `isValidDocId`) and reads the documents with one
    `getAll`. It refuses 404 unknown id, 400 link, 400 path outside `session-materials/{sessionId}/`,
    404 missing Storage object (by filename), 500 unreadable size, and 413 `too-large` past 200 MiB.
    It commits one `admin_logs` row per file in one batch, and sends nothing when that commit fails.
    It then streams a stored zip (`yazl` 3.3.1, `addReadStreamLazy`, one Storage read stream open at
    a time) with `application/zip`, `attachment; filename="session-materials.zip"`, `no-store`, and
    no Content-Length.
  - The handler watches for the response closing from its first line. An admin who leaves during the
    checks or the audit commit gets no archive built and no Storage read opened, and the handler
    returns. Every error after the first byte reaches one `fail`, which destroys the read stream and
    the response and never ends it. Once the archive has settled, the next entry opens no read.
  - Entry names are `{sessionId}/{filename}`. Each part is composed to NFC; separators, control
    characters and `<>:"|?*` become `-`; leading and trailing dots and spaces go; a Windows device
    name takes a leading `_`; the part is cut to 240 UTF-8 bytes on a code-point boundary, with the
    extension and any ` (n)` kept, and the end is stripped again after the cut. A repeat in one
    folder, compared without case, takes ` (2)`, ` (3)`.

## Departures from the spec

1. **E2E added** (the spec said none). The director asked for it as the real-surface proof.
2. **`AdminApp.jsx` edited**: The materials route loads lazily through `DeferredAdminPage`. Spec §8
   said not without the director; the dispatch allowed it.
3. **`requireAdmin` gets `db`** (`{ auth, db, getConfig }`). a4 made every admin gate read
   `config/bootstrap` live and fail closed through `db`; the spec's call left it out.
4. **Entry names do more than the spec's cleaning.** They also replace `<>:"|?*`, compose to NFC,
   cap at 240 UTF-8 bytes (the spec said 150 characters), strip trailing dots and spaces before and
   after the cut, and prefix Windows device names. The colon is required: yazl's
   `validateMetadataPath` throws "absolute path" on a name that starts like a drive letter, and a
   Firestore session id can be `c:talk`. The rest came from the review round.
5. **Link refusal wording**: "materialIds: m2 is a link. Only files go in an archive." With the
   spec's "… is a link; only files …", `fieldErrorsOf` would cut the message in two, because it
   splits on `'; '`.
6. **Size parsing**: Only a whole number of bytes passes (a decimal string or a number).
   `Number('')` is 0, which "finite after `Number()`" would accept.
7. **The selection is read against the file rows on screen.** The spec drops ids that are no longer
   file rows after a load. This also drops a row that a review change filtered out, so an archive
   never holds a file the admin cannot see.
8. **Coverage day label** comes from the live `dayId` (`resolveDayLabel`), with the same fallbacks
   as the sessions list, since the title and speakers come from the live document too.
9. **Refresh, not Reload** (review round): The admin's word elsewhere.

## Decisions the owner may want to change

- Sort words: Material "A to Z" / "Z to A", Session "Schedule order" / "Reverse schedule order",
  Changed "Newest first" / "Oldest first". The first press on Changed is newest first.
- The archive result line clears on any selection or filter change and on the next press. The two
  refusals before a request ("Select at least one file.", "An archive holds at most 50 files. 51 are
  selected.") are caution notices (`role="status"`).
- Try again says "Loading…" while it retries, as the Access page's does; Refresh says
  "Refreshing…".
- An admin who leaves during the audit commit still has the audit rows written: The rows record the
  request, and the archive is then not built.
- The 2,000-row cut takes the first rows in document-id order (Firestore's default). The notice says
  that some materials are not shown; it does not name them.
- A speaker id with no record is listed as the id in the data face, with no link, because there is
  no record to open. The speaker list is sorted by name and hidden when empty.
- "Read at" is the time the list response arrived, on the event clock with the zone name.
- `listAllSessionMaterials` also sends `Cache-Control: private, max-age=0, no-store`.
- Spec Q1 stands: `uploadSessionMaterial` still accepts any `storagePath`, and
  `downloadSessionMaterial` still streams it; only the archive checks the prefix. An issue is needed
  before #213.
