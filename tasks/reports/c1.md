## Where the build departs from the spec, and why

1. **The proof tint is on the cells, not the `<tr>`.** The spec says "A `<tr>` that is not Live
   takes `proofRowClass`". Built that way, a screenshot of the list in Chromium showed every Draft
   row pushed one column to the right: `proofRowClass` draws its ground as a `::before`, and a
   pseudo-element on a table row takes a cell slot. Each cell of such a row now takes the class and
   holds one element, so the tint rule lifts the content above the ground. The fix is its own
   commit; the page test pins "no `<tr>` carries it, every cell does", and the E2E checks that each
   cell of the draft's row starts under its head.
2. **The table region is bounded** (`max-h-[36rem]`), as the ticketing tables are. The spec copies
   the sticky galley head; a sticky head in a box that never scrolls down pins to nothing (a3's
   finding on the public table).
3. **Local errors show after the first save attempt**, not while a blank create form is being
   filled, and the form has `noValidate` so the browser's own bubble does not preempt the marks.
   A category with a control character (a pasted tab) gets a fourth local message, "Use one line
   of plain text.", beside the spec's three.
4. **A publish that fails after a good save** is titled "The draft is saved, and it is not
   published", and a new update moves to its own address, so the retry is an edit of the same id.
   A refused delete is titled "The server refused the delete".
5. `dayInZone` falls back to the reader's clock for no zone or an unknown one, the same fallback
   the public dateline takes; the changed-day rule (noon UTC) is as the spec says.
6. The path and copy constants (`UPDATES_ROOT`, `NEW_UPDATE_PATH`, `UPDATES_OFF_MESSAGE`) and
   `placementOf` live in `updatesDoc.js`, so the two lazy pages do not import each other.
7. On the public page the "Pinned" tag now reads `pinned === true` (it read any truthy value), the
   rule the sort and the runs already used.

## Decisions the owner may want to change

- The docket item is "Updates", beside "Live updates", with the description line to tell them
  apart. The spec's default.
- The lead is chosen by the feed's order (pinned, then newest). Nothing stops two featured posts;
  the second keeps its place. No server rule for one featured post.
- The category cap is 24 characters, so the tag fits a 320 pixel screen. The category is on the
  list only, not the update's own page, and is not a filter.
- `featured: null` is refused, like any other non-boolean.
- The E2E seed leaves `features.updates` off, so the spec turns it on in `beforeAll` and restores
  the stored document in `afterAll`.
