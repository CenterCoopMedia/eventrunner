# w5 report: issue #200, live update categories, audience, and key dates

## What changed

- `firestore.rules`: `live_updates` is no longer `allow read: if true`. A row is readable when its
  `audience` is in `readableLiveUpdateAudiences()`: signed out, `everyone`; an approved attendee,
  `everyone` and `attendees`; a speaker (`users.speakerId` set), all three. Admins (either tier)
  read every row. A row with no audience or an unknown one is admin only (fails closed).
- `firestore.indexes.json`: two composite indexes for the card's queries
  (`audience` + `postedAt desc`, and `pinned` + `audience` + `postedAt desc`).
- `functions/src/admin/liveUpdates.cjs`: `saveLiveUpdate` accepts `category` (the shared
  `validUpdateCategory` rule, 24 characters, one line) and `audience` (`everyone`, `attendees`,
  `speakers`). Both are always stored. An edit that omits either keeps the row's value, so an
  admin tab on an older bundle cannot widen a speaker-only row. A new row, or an old row with
  no audience, gets `everyone`. The `admin_logs` row now carries `details: { audience,
  previousAudience }`.
- `apps/web/src/lib/liveUpdatesSource.js`: both queries carry `where('audience', 'in', list)`.
  `readableAudiences()` gives the same list the rules give.
- `apps/web/src/hooks/useLiveUpdates.js`: reads the list from the reader's own account
  (`useAuth`, `useProfile`), listens again when it changes, and drops the rows read for an older
  list (a sign-out does not keep speaker rows on screen).
- `apps/web/src/components/LiveUpdatesCard.jsx`: category and audience tags in words ("For
  speakers", "For attendees"); a "Key dates" section from `config/event.milestones`, in date
  order then name order, with the year. Key dates show when the feed is empty and do not wait for
  the feed. Nothing renders when both are empty.
- `apps/web/src/lib/milestones.js` (new): `sortMilestones` and `utcDay`, moved from
  `admin/overview/milestones.js`, which re-exports `sortMilestones`. The admin overview and the
  public card use one ordering.
- `apps/web/src/admin/pages/AdminLiveUpdates.jsx`: "Category" field and "Who can read it"
  select. Each row shows its audience and category as words. A row with no audience shows
  "Admins only, no audience set", and a notice counts them. Opening one starts on Everyone.
- `functions/src/admin/exportFixture.cjs`, `eventPackage.cjs`: the fixture row and the package
  file description carry the new fields.
- Docs: `docs/ADMIN_GUIDE.md` (Live updates fields, old rows, key dates; Milestones note),
  `CHANGELOG.md` (Added; Changed with the upgrade note and the index deploy), `docs/ROADMAP.md`
  (#200 ticked). `docs/docs/**` regenerated.

## Decisions the owner may want to change

1. Three audiences: `everyone`, `attendees` (approved attendees and speakers), `speakers`.
   Admins read everything. "attendees" uses the existing `requesterIsApprovedAttendee`, so a
   speaker sees attendee rows; a ticketed but not approved account sees only `everyone`.
2. Rows saved before this change have no audience and become admin only. They leave the public
   card until an admin opens and saves each one. No automatic backfill. If the owner wants old
   rows public without an edit, a one-time backfill script is the follow-up.
3. Admins see all three audiences on the public card (with the audience tag). They do not see
   the card "as an attendee".
4. Key dates show every milestone, past ones included, as the admin overview does.
5. Old clients: a browser still on the previous bundle sends the card query with no audience
   predicate, which the new rules refuse. The card stays empty for that reader until a reload.
