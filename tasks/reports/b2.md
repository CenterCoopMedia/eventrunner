## What changed

`systemErrorsAdmin.cjs` shape: POST only, `applyCors`, the gate first, `core/errors.cjs`.

- `listSentEmails { q?, source?, status?, limit?, cursor? } → { rows, nextCursor, scanned }`.
  The query is `.select(...LIST_FIELDS)`, and `LIST_FIELDS` holds no `html` and no `text`, so a
  list never takes a body out of Firestore. With no `q`, one query reads `limit + 1` rows (at most
  51). With `q`, one query reads at most `SCAN_CAP = 500` rows. It keeps a row when `to` or
  `subject` contains `q` (case is ignored), and it stops at `limit` matches. `nextCursor` is the
  last row it examined. Each 400 names its field and never repeats the value. List requests write
  no `admin_logs` row.
- `getSentEmail { id } → { row }`: the list fields plus `html`, `text`, `providerMessageId` and
  `providerStatus`. A missing row answers 404. A successful read writes one `admin_logs` row:
  `action: 'view-sent-email'`, `docPath: 'sent_emails/<id>'`, the actor's uid and email, and `at`.
  The row holds no recipient address and no subject.
- `isValidDocId` checks both `id` and `cursor.id`, so a bad id is a 400 and never a thrown `doc()` or
  `startAfter()`.

### What a browser does with each frame attribute and each directive

| Item | What the browser does |
|---|---|
| `sandbox=""` | Sets every sandbox flag. The document gets an opaque origin, so it cannot read the admin page, its storage or its token. Script is off: `<script>`, inline handlers and `javascript:` URLs do not run. Forms do not submit. Popups and new windows are refused. The frame cannot navigate the top page. Plugins, modals and downloads are off. The frame CAN still navigate itself, and neither the sandbox nor the policy stops that. That is why the builder removes every link target (see "The review round", problem 1). |
| `srcdoc` | The frame's document comes inline, as `about:srcdoc`. Loading the frame fetches nothing. |
| `referrerpolicy="no-referrer"` | A request from the frame element carries no `Referer`. There is no such request with `srcdoc`, so this attribute is a spare barrier. |
| `title` | The frame's accessible name, "Message to {to}". |
| `[color-scheme:light]` (class) | Sets the frame element's used colour scheme to light, so `prefers-color-scheme` inside the frame reads light (see Departures). |
| Policy meta first in `<head>` | A meta policy governs only what the parser meets after it, so it comes first. |
| `default-src 'none'` | This is the fallback for script, connect, font, frame, media, object, manifest and worker. The browser refuses every fetch of those kinds. It also refuses every script, inline or remote, because the policy has no `'unsafe-inline'` for script. |
| `img-src data:` | Only `data:` images load. Remote images, relative images, `srcset` and CSS `url()` backgrounds are refused before the request leaves the renderer, so a tracking pixel learns nothing. |
| `style-src 'unsafe-inline'` | Inline `<style>` and `style=""` apply, and mail depends on them. An external stylesheet or `@import` is refused. |
| `form-action 'none'` | A form cannot submit anywhere. This is the second barrier after the sandbox. |
| `base-uri 'none'` | Any `<base href>` is ignored. This is the second barrier after the DOMParser pass removes stored `base` elements. |

## Departures from the spec, where the code proved it wrong or short

1. **Links are turned off, not sent to a new tab.** The spec forced `target="_blank"` on
   `a[href]` and `area[href]`. The first round extended that to every `a` and `area`, and said this
   closed the spec §4 residual risk. That claim was false: the review showed three ways to put the
   target back or to bring a link past the pass (problem 1 below). The builder now removes every
   `href` and `xlink:href`, and it removes more elements than the spec named: every stored `meta`
   (not only `meta[http-equiv]`), every `template`, `form`, nested frame and embedded object, and
   every SVG animation element. It also settles the markup to a fixed point, and it falls back to
   the plain text when the markup does not settle. The spec's residual risk is closed: the E2E probe
   clicks each payload and sees no request.
2. **The E2E network proof reads each request's outcome, not the bare request list.** Spec §5
   says that no request names `pixel.example.test`. In Chromium, `page.on('request')` does see a
   request that the content policy refuses: it fires, and then `requestfailed` fires with the
   reason `csp`, and nothing leaves the renderer. The first run failed on that assertion. The spec
   now asserts that every such request fails with `csp`, that none gets a response, and that the
   link raises no request at all.
3. **`[color-scheme:light]` on the iframe element.** Inside a frame, `prefers-color-scheme`
   follows the embedding element's used colour scheme. The admin sets none, so without this class
   a mail's own dark-mode rules could switch on under a dark system setting while the preview draws
   the light canvas. This supports spec §3's "a light mail client … in both admin modes".
4. **Subject cell.** "Not stored" shows when `bodyStored` is false. "No subject" shows when a body
   was stored but the subject is null, for example a failed send with no recipient. The spec said
   "(or 'Not stored')" for both.
5. **The empty search-window state counts what was examined.** Its heading reads "No match in the
   500 most recent messages" after one window and "…1,000…" after the next, and the pager reads
   "Search older messages". The "read at" time in the figure sentence uses the event clock and
   zone label, the same as the Sent column, for example "read at 10:13 PM UTC".
6. **Privacy additions.** The search field has `autocomplete="off"`, so a searched address does
   not go into the browser's form history. A 400 never repeats the value it refused. A 403 hides
   the form as well as the table.
7. **`getSentEmail` writes its audit row only on a successful read.** A 400, 403 or 404 writes
   none, because no mail was read.
8. **The shared `signIn` has three importers, not two.** a4 added a third copy in
   `admin-access.spec.js` after the spec was written, and that spec now imports the shared helper
   too.
9. **The URL keeps only a source the page names.** The spec allowed any `[a-z0-9-]` source id in
   the URL. The page now keeps a source only when it is an own key of its label map (problem 4).
   A row with any other source still shows that id in the data face.
10. **Load more waits for a running search.** While a search or a refresh runs, the pager has
    `aria-disabled="true"` and its handler refuses (problem 3). The spec did not cover this case.

## Decision 10: deviations from the design record, for the director to accept

- **No sort control**, though design record §8 lists #183 under the sort control. The server
  order is newest first. A client-side sort of one page would mislead, because it would reorder
  only the rows loaded.
- **No bulk-action row** (design record §3.4). The log has no action to apply to a row.
- **The search text stays out of the URL**, though design record §3.3 keeps a query there. An
  address in the URL reaches client error reports: `lib/errorReporting.js` sends
  `window.location.href`, and `telemetry/redact.cjs` misses a `%40`-encoded address. Source and
  status do stay in the URL.

## Decisions the owner may want to change

- Staff see every row, operator alerts included (open question 1). An operator-only carve-out
  would need a different query and index.
- The Sent column and "read at" use the event clock with its zone label. With no `timezone`, or an
  invalid one, they use the reader's clock and its label (open question 2).
- Search is a bounded scan of 500 rows per request with no new field, and status filters the
  stored `sent`/`failed` only (decisions 1 and 2). Delivery state shows as a word on the row.
- The page, both endpoints and the docket entry are staff tier (decision 5).
