## 1. Get tickets showed before any catalog existed

- Change: `apps/web/src/lib/useRegistrationLink.js`. The hook already reads the
  public `ticketingCatalog` response that `/tickets` uses. It now also reads
  `catalogRevision` from that response. The server sets it only for a published
  catalog, and `/tickets` already reads the same field before it accepts terms.
  No second source was added, and the server did not change.
- Behaviour: Stripe with no published catalog shows no ticket action, and the
  external URL is not used. A published catalog shows **Get tickets** also while
  sales are paused or every window is closed, so the visitor reads the closed
  reason and the sales dates. A failed lookup keeps **Get tickets**, as before.
  Eventbrite, manual and none are unchanged.
- Tests: `apps/web/src/components/RegistrationActionStripe.test.jsx` ("shows no
  ticket action before a Stripe catalog is published", "keeps the native action
  while a published catalog has paused sales or closed windows"); the first
  failed before the fix. Browser: `e2e/stripe-ticketing-ui.spec.js` "the header
  and home lead offer tickets only once a catalog is published" renders the real
  home page and `/tickets`. Rehearsal rerun on the real Stripe-provider endpoint:
  header before the catalog has no Get tickets link; after publish it has
  `Get tickets -> /tickets`.
- Docs: `docs/ADMIN_GUIDE.md` launch step 3 and the register-control paragraph.
  That paragraph also said a failed lookup keeps the external action; the code
  keeps Get tickets, and the paragraph now says so.
- Met in full.

## 2. Warning after Reopen new sales with no edits

- Change: `apps/web/src/admin/components/StripeCatalogPanel.jsx`. The editor
  keeps the saved catalog it last loaded (draft and price inputs) as a baseline.
  When the saved revision moves and the editor still equals the baseline, it
  loads the new catalog silently. Real edits keep the warning, the disabled save
  and the reload control.
- Tests: `apps/web/src/admin/components/StripeTicketingWorkspace.reopen.test.jsx`
  renders the whole workspace and uses the real reopen dialog: no warning, Pause
  new sales unchecked, the next save sends the new revision with sales open;
  real edits keep the warning; an edit typed back to the saved value counts as
  no edit. Two of the three failed before the fix. Browser:
  `e2e/stripe-ticketing-ui.spec.js` "reopening sales updates an unedited catalog
  editor without an unsaved-edits warning". Rehearsal rerun: `admin-05d-sales-open.png`
  has no warning; a pause and reopen with the editor open logged 0 warnings.
- Met in full.

## Decisions the owner may want to change

- "Published" is read as `catalogRevision` being a non-negative integer in the
  public catalog response. A published catalog on a historical-demo event also
  answers null; such a site shows no action, which matches its read-only state.
- Paused or closed sales keep Get tickets (the simplest correct answer in the brief).
- The header lookup cache stays at 30 seconds, so an already open tab can show
  the old state for up to 30 seconds after a publish.
- Empty cart: a stated prompt and an enabled Continue, not a removed or disabled
  button. The total line ("Total for 0 tickets $0.00") and the refund policy stay.
- Sales-window time entry and timezone controls were not changed.
