## Design

- `config/bootstrap.adminEmails` keeps its meaning and becomes the **operator** list. Every
  existing deployment keeps full access with no migration. `config/bootstrap.staffEmails` is the
  new **staff** list. Any admin is on either list; an operator is on `adminEmails`; an address on
  both is an operator. Both lists are stored lowercase.
- Rules: `isVerifiedSignIn()`, `bootstrapAllowlist(field)` (reads the field with a `[]` default so
  a pre-split document works), `isOperator()`, `isStaff()`, `isAdmin()` = either. Every
  admin-readable collection reads on `isAdmin()`; `admin_logs` reads on `isOperator()`.
- Server: `functions/src/core/auth.cjs` exports `ADMIN_TIERS`, `resolveAdminTier(bootstrap,
  email)`, `loadBootstrap`, `BootstrapUnavailableError`, `BOOTSTRAP_UNAVAILABLE` and
  `requireAdmin(deps, req, { tier })`. The option defaults to `'operator'`, so an endpoint that
  does not state a tier refuses staff. Every existing `requireAdmin` call states its tier at the
  call and passes `db`. With `db` the gate reads `config/bootstrap` live and **fails closed**: a
  read that throws answers 500 and admits nobody; an absent document means no admins; the cached
  copy is never consulted. Only `requireAttendeeAccess` (no `db`) reads the five-minute cache, on
  purpose. The three hand-rolled `adminEmails` scans (`speakers/profile.cjs`, `media/upload.cjs`
  twice) use `resolveAdminTier` over the same live read; `materials/actor.cjs` surfaces a failed
  read as 500 on a write and as not-admin on the optional read.
- `config/event.sender` is the operator's to **change**: `admin/config.cjs` compares a sent sender
  with the stored one inside the write transaction (email and reply-to case-insensitive, name
  trimmed, empty as null) and refuses a staff save only when a value differs. The Event form does
  not send the block for staff at all and shows the three fields read-only with a one-line note.
- Branding is the operator's in the media library too: `mediaUpload` into `branding/`,
  `mediaDelete` and `mediaUpdateMetadata` on a branding asset (folder or `branding/` path), and
  `mediaDelete` of any asset a `config/theme` slot references, force or not, gate at staff and then
  ask for the operator tier. A staff delete whose usage scan fails is refused even with force.
- Client: `AuthContext` runs a second rules probe (`admin_logs`, limit 1) beside the drafts probe
  and exposes `adminTier` (`'operator' | 'staff' | null`) and `isOperator`; `adminStatus` stays
  `'unknown'` until both probes answer. `AdminLayout.jsx` is the one place a page declares its
  tier: every `DOCKET` item carries `tier`, `docketForTier` hides the rest, and
  `sectionTier(pathname)` (percent-decoded, lowercased, the way the router matches; a path no
  staff section owns is the operator's) plus `tierReaches` render a refusal in place of `<Outlet />`
  for an out-of-tier route. `TIER_SCOPE` names each tier's sections from the docket in the rail's
  own words for the refusal, the Access page's description and its confirmation sentences.
- WebMCP: each admin tool declares a tier mirroring its endpoint; `adminToolsForTier` mounts the
  set the tier holds.
- Access page (#187): `functions/src/admin/access.cjs` with `listAdminAccess` and `setAdminAccess`
  (both operator-only, both read `config/bootstrap` fresh). `setAdminAccess { email, tier:
  operator|staff|none }` lowercases, moves the address between the lists in a transaction, refuses
  409 `last-operator` when the result would have no operator (the caller's own grant included),
  answers `changed: false` without a write for a no-op, writes an `admin_logs` row through the
  shared `logAdminAction` (optional `details`: `{ email, tier, previousTier }`), and refreshes its
  own container's config cache. The page is one ruled table with the tier as a badge word, the
  caller's row marked "(you)", quiet row actions, a grant form, and one still confirmation surface
  under the grant form for every change; focus moves in effects after render (onto the surface,
  back to the trigger or the grant field, onto a refusal); an already-held tier is stated in place
  with no confirmation; a failed first load is an error state with one retry.
- `init-event.cjs` takes `--staff`; the answers file takes `staffEmails`. On a re-run against an
  existing `config/bootstrap` the answers file's lists are not re-applied: only explicit `--admin`
  and `--staff` add, the merge stays additive, and the output names what was added. The readiness
  "two admins" row counts operators only.

## Decisions the owner may want to change

- **Event settings are staff**, with the sender held back only on change. Badges are staff.
  Ticketing operations are staff (provider setup lives in Tier A env and operator scripts).
- **`admin_logs` is operator-only** and doubles as the read the browser probes to learn its tier.
  If a later page needs staff to read it, the tier probe needs another operator-only read.
- **Fail-closed on an absent `config/bootstrap`** with a `db`: a deployment whose bootstrap
  document is deleted has no admins until it is written again (init-event, or the Admin SDK).
- **A path no staff section owns is the operator's** in the shell, so `/admin/nope` shows the tier
  refusal to staff rather than "Admin page not found". The server was never affected.
- **A no-op grant writes no `admin_logs` row** (`changed: false`); `approveUser` logs no-ops.
- Storage rules do not check admin at all (they cannot read Firestore), so `storage.rules` and its
  tests are unchanged.
- The review fixes are two commits (one per issue) after the two feature commits rather than
  amended into them, so the review's findings and their fixes are readable as a diff.
