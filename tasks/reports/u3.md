# u3 report: firebase-admin 14 and React Router 7

Branch `joe/wave3-u3`, cut from `origin/main` at 0591e06. Two commits carry the work. This
report is the third. Nothing is pushed. The rebuilt `docs/demo` and `docs/docs` are not
committed.

## What changed

### Cloud Functions: firebase-admin 14.5.0 and firebase-functions 7.4.0

- `functions/package.json`: `firebase-admin` ^13.4.0 to ^14.5.0, `firebase-functions` ^6.4.0
  to ^7.4.0. Both lockfiles are updated.
- firebase-functions had to move too. Every 6.x release, and 7.0 to 7.2, accepts
  firebase-admin up to 13 only. 7.3.0 is the first release that accepts 14.
- `npm install -w functions` put the new packages under `functions/node_modules` in the root
  lockfile. Root scripts and E2E helpers (`e2e/helpers.mjs`, `scripts/dev/invite-smoke.mjs`)
  then could not resolve `firebase-admin`. I removed the nested entries and let npm
  re-resolve them, so firebase-admin is hoisted to the root again, as on main.
- `functions/src/users/records.cjs`: `isUserNotFound` reads `err.code` only.

### Web app: React Router 7.18.4

- `apps/web/package.json`: `react-router-dom` ^6.30.1 is replaced by `react-router` ^7.18.4.
- I followed the official v6 to v7 upgrade guide:
  1. Future flags. `main.jsx` and the branding proof already set `v7_startTransition` and
     `v7_relativeSplatPath`. The other flags apply only to data routers, and the app does not
     use one. So the app already behaved as v7 does.
  2. Package swap. Every `react-router-dom` import in 170 files now names `react-router`. v7
     exports `BrowserRouter`, `HashRouter`, `Link` and `NavLink` from that package. The app
     uses nothing that the guide moves to `react-router/dom`.
  3. The `future` props are v7 defaults now, so I removed them from `main.jsx`, the branding
     proof and the tests.
- The app stays a plain single-page app in declarative mode. It has no framework mode, no
  data router and no React Router Vite plugin. A deployment uses `BrowserRouter`. The demo
  uses `HashRouter` under `/eventrunner/demo/`.
- The branding proof's nested `MemoryRouter` uses `UNSAFE_RouteContext` and
  `UNSAFE_LocationContext`. Both still exist in v7, with the same default shape.

### Other files

- `scripts/ci/audit-exceptions.json`: the `firebase-admin` and `react-router-dom` entries are
  removed, because those findings are gone.
- `CHANGELOG.md`: two entries under Unreleased, Changed.
- No other doc names these versions. `docs/performance/public-bundle-report.md` lists
  `react-router` in a dated size table, so I left it as it is.

## Breaking changes handled

firebase-admin 14.0:

- Instance ID service removed: not used.
- Legacy namespace (`admin.firestore()` and similar) removed: not used. Every import names a
  modular subpath (`firebase-admin/app`, `/auth`, `/firestore`, `/storage`). This covers
  `functions/`, `scripts/`, `e2e/`, `tests/` and `video/`.
- Legacy FCM types removed: FCM is not used.
- Node 18 and 20 dropped: the functions already declare Node 22.
- Error handling rework: `err.code` still reads `auth/user-not-found`, which I checked on a
  real `FirebaseAuthError`. The public `errorInfo` field is gone, so I removed the
  `err.errorInfo.code` fallback in `records.cjs`. The `attendee-admin` E2E spec reads that
  code from a real emulator call, and it passes.
- 14.1 to 14.5 list no breaking changes. Their deprecations (FCM `token`, Machine Learning)
  do not touch this code.
- The transitive packages also change major version: `@google-cloud/firestore` 7 to 9,
  `@google-cloud/storage` 7 to 8, `google-auth-library` 10 to 11. Their changelogs list Node
  version floors and TypeScript typing changes only.

firebase-functions 7.0:

- `functions.config()` removed: not used. Settings come from `firebase-functions/params`.
- v1 `Event` type renamed to `LegacyEvent`: not named.
- Node 16 dropped, and the emulator returns 500 at once for an unhandled async `onRequest`
  error: no change needed.
- The only v1 use is the `onUserCreated` and `onUserDeleted` auth triggers
  (`runWith().region().auth.user()`). They still exist in 7.4. Loading `functions/index.js`
  gives the same 121 exports.
- 7.4.0 moves its own `express` dependency from 4 to 5. I searched the handlers for Express 4
  calls that Express 5 removed: `res.send(status)`, `res.json(obj, status)`, `req.param()`,
  `redirect('back')` and writes to `req.query`. None are used.

React Router 7: see the steps above. `json` and `defer` were removed in v7, and the app does
not use them.

## Decisions for the owner

- firebase-functions 7 is a second major upgrade. Its peer range made it necessary. Deploy
  to a staging project before production: the deployed runtime supplies `req` and `res`, so
  only a real deploy proves the handlers there.
- The initial demo bundle grows from 282,477 to 287,507 gzip bytes (+5,030). That leaves
  4,493 bytes under the 292,000 ceiling. The app build is at 285,795. A later feature can
  reach the ceiling sooner. Raise the budget or trim the entry chunk when that happens.
- The integrator must regenerate `docs/docs` (changelog page) and `docs/demo` on the stack
  tip. This branch changes the web bundle and `CHANGELOG.md`.
- u2's firebase-tools 15 branch also changes the root `package-lock.json`. Expect a lockfile
  conflict. To resolve it, run `npm install` on the joined `package.json` files. Do not merge
  the lockfile by hand.
