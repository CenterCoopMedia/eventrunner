## What changed

Server, `functions/src/cms/versions.cjs` (the only server file changed). `cmsGetVersionHistory`
keeps its request, its limits, its staff gate (a4) and its `{ entries, nextCursor }` shape. Each
entry is now built by `toEntry` from named fields only: `id, docPath, revision, visible,
publishedAt, publishedBy, publishedByUid, previousRevision, changes, moreChanges`. The stored
field snapshot is no longer sent: the page reads the changes only.

- `publishedAt` is milliseconds. A Firestore Timestamp has no `toJSON`, so before this change it
  left as `{ _seconds, _nanoseconds }`.
- `changes` comes from `describeChanges(previous, current)` (pure, in `internals`). The
  predecessor of each entry is the next row of the same query. The query already reads one row
  past the page for `nextCursor`, so the last entry on a full page has its predecessor too, with
  no extra read. Fields flatten to dotted paths: a map by key, an array of scalars as one value,
  any other array by index, an empty map or array as one value. When either side of a leaf is a
  time, the two sides match when they name the same instant, and both leave as milliseconds,
  marked `time: true` (a seeded ISO string beside a Timestamp included). `seeded` and `seededAt`
  are never a change. `visible` shows when it moves, and on a first version that went out hidden.
  Paths sort segment by segment, an index by number. At most 50 changes; `moreChanges` counts the
  rest.
- No new endpoint, collection, index, rule, queue or `admin_logs` row. `functions/index.js` and
  `.github/smoke-endpoints.json` are unchanged.

## Departures from the spec, and why

1. **The record list uses b1's `RuledTable`** (`admin/components/RuledTable.jsx`, on the base
   since the spec was written) instead of a copy of `GalleyHead`'s classes. It draws the same
   sticky head, the focusable region named by its caption ("Records"), and `aria-sort`.
2. **Page tests mock `useAdminApi`**, not `fetch`: the convention the email log and attendee page
   tests follow, and the one the dispatch message names for the shell.
3. **`describeChanges` returns `{ changes, moreChanges }`**, so "no change" is
   `{ changes: [], moreChanges: 0 }`, and the cap lives in one place.
4. **The entry sends no `fields` snapshot.** The spec kept it "as stored" so the existing cases
   pass. Stored, a Timestamp in it would still leave as `_seconds`, and the page does not read it,
   so it is dropped; the one existing case that read it reads `changes` instead.
5. Additions the spec did not ask for: the line on the live version, the Hidden mark in the list
   (the Pages list's idiom), and the pager's stated refusal (review round).

## Review round

The review confirmed eight findings. Three major ones were all in the restore, which the spec had
left out (open question 1) and the first dispatch asked for; the director has since withdrawn that
request.

### Removed: the restore (findings 1 to 3)

- **What:** the "Restore version N" button, its confirmation, "Publish now" on the page,
  `restoreRequestFor` and its helpers in `versionHistory.js`, their tests (5 helper cases, 7 page
  cases), E2E case 3, the restore copy in ADMIN_GUIDE and CHANGELOG, and the `fields` snapshot
  with its ISO-string conversion (`jsonSafe`) in `versions.cjs`, which only the restore read.
- **Why:** a restore through the save endpoints skipped rules that live only in the editors. A
  restored deleted block could go past its section's `maxBlocks` and outside its `allowedBlocks`
  (finding 1). A restore skipped the editor-only field rules, such as an empty image alt and
  session times, and the server answered 200 (finding 2). A restore over unpublished changes
  dropped them behind a plain confirmation, not the destructive treatment (finding 3). A safe
  restore needs those rules on the server, in `content.cjs`, which c2 and c3 also edit, so it
  becomes its own issue.
- **Now:** the page is read only, as the spec has it; ADMIN_GUIDE says versions cannot be
  changed or restored. The E2E proof is the spec's: edit and publish a record, open its history,
  and read what changed, when, and by which account.
- Commit `bb28669` Remove the version restore from the version history page. The removal has no
  failing-first test; the page test "shows what changed, when, and by which account" now also
  asserts no restore control and no call but the history read.
