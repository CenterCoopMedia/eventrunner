An event CMS that staff can run without editing code

Event Runner is a white-label event CMS. Each client event uses a separate Firebase project. The Center for Cooperative Media deploys and operates the service. Staff manage the schedule, speakers, pages, registration, and event updates in the admin panel.

What v1 includes

Schedule and speakers

Sessions, bookmarks, and ICS calendar links. Staff can invite speakers, review profiles, approve changes, and publish an attendee directory.

Block CMS and sign-in

A draft-and-publish block CMS for pages and event content. Attendees can use Google sign-in or an emailed six-digit code.

Ticketing

Eventbrite and manual CSV adapters use one provider-neutral registration state machine.

The triage record lists the full v1 scope and excluded features.

How it is deployed

Each client event uses a separate Firebase project. The Center for Cooperative Media deploys and operates it. The client data, sender domain, and ticket-provider settings stay in that deployment. Client staff use the admin panel. They do not manage a repository or server.

The code uses the Apache-2.0 license and can be read, forked, or self-hosted. The Event Runner product name is reserved to the Center for Cooperative Media.

For event operators

Event Runner is for nonprofits, newsrooms, universities, and event producers that need a staff-managed event site. It includes schedules, speakers, registration, pages, and session materials.

For contributors

The reference implementation is the 2026 Collaborative Journalism Summit site. That repository remains the live event site. Event Runner is a separate public extraction that accepts contributions under Apache-2.0.
