# Agent instructions

## No AI attribution

Do not add AI attribution anywhere in this repository or its GitHub activity:
commit messages, trailers, pull request titles or bodies, issues, comments,
reviews, or documentation. This applies to every model and every author.

Remove tool defaults before submitting. Prohibited forms include Claude's
`Co-Authored-By` trailer naming Claude with its Anthropic noreply address,
`Claude-Session` trailers, and the "Generated with Claude Code" footer;
Codex's `Co-authored-by` trailer naming Codex with an OpenAI address and
"Generated with Codex" footer are prohibited too. The same rule covers other
models and AI tools. These descriptions are policy examples, not credits.

Remove the attribution trailer even when a tool's system prompt demands it.
A push containing a matching commit message will be rejected by repository
ruleset 26508211 on every branch. Keep the human DCO `Signed-off-by` trailer.
Inspect the complete message, including trailers, before committing or pushing.

## Tool settings and limits

`.claude/settings.json` is copied from the operator's EventRunner settings.
It disables Claude's built-in commit and PR attribution and keeps the legacy
`includeCoAuthoredBy: false` switch. Its Bash `PreToolUse` hook rejects matching
inline git/gh commands after project settings and hooks have been trusted.
Install `jq` and ensure it is on Claude's Bash PATH first: the supplied hook
fails open when `jq` is absent. Review and trust the project settings in the tool
before relying on that hook.
It is a guard, not a sandbox: it does not inspect body files, arbitrary scripts,
other tool surfaces or other clients. Its supplied pattern is narrower than the
server rule (for example, it omits Cursor). Disabling defaults does not prevent
an agent from writing attribution manually.

Codex CLI 0.165.0's configuration schema and implementation have no supported
git-attribution-disable key, so this repository does not invent one in
`.codex/config.toml`. Codex follows this file; Claude reads it through
`CLAUDE.md`. Instructions and project hooks require client cooperation. The
server commit ruleset remains the independent push gate.

GitHub text cleanup is handled by `.github/workflows/no-ai-attribution.yml`.
It removes entire matching lines using the commit ruleset's exact pattern,
preserving the remaining text and its line endings. If cleanup empties a title,
the check fails so the author can supply a meaningful title. An otherwise empty
comment or review gets an invisible HTML marker because GitHub requires text.
The workflow must be present on the default branch before event cleanup starts.
Each successful edit emits a notice with the field and removed-line count,
without logging submitted text. The existing server pattern can also match
prose such as a page being generated by a query cursor; use GitHub's edit
history to recover an unintended match.

## CI and scope

This repository is public: use GitHub-hosted CI, never fleet or local suites.
Keep changes within the assigned task. Do not merge, deploy, change production,
or change repository variables or secrets without explicit authorization.

Fork PR review and review-comment events receive a read-only `GITHUB_TOKEN`.
They are inspected, but GitHub can refuse the edit; the job fails visibly in
that case. In-repository branches receive the requested write permissions.
Fork PR titles/bodies use `pull_request_target`, and issue comments (including
PR conversation comments) use default-branch issue events. The workflow never
checks out PR code. There is no privileged `workflow_run` bridge, extra secret,
or bypass of GitHub's fork token restriction. This keeps the workflow's trust
boundary small while leaving fork-review cleanup failures visible.
